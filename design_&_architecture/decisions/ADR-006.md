# ADR-006 — Salvataggi (save state + SRAM + export/import)

## Contesto

Con gli emulatori reali (WasmBoy/mGBA), si abilita EP-004: save state multipli (US-016), SRAM in-game (US-017), associazione al gioco (US-018), export/import (US-019). [^src: management/kanban/EP-004-salvataggi/US-016-save-state-multipli/US-016.md §Acceptance Criteria]

Lo schema di persistenza è già definito ([[indexeddb-stores]], ADR-002): store `saveStates` (per slot, per rom) e `sram` (per rom). [^src: management/kanban/EP-004-salvataggi/US-018-salvataggi-associati/US-018.md §Business Rules]

## Decisione

1. **Estendere `EmulatorEngine`** ([[ADR-003]]) con i salvataggi:
   - `snapshot(): Promise<Uint8Array>` — istantanea dello stato (save state).
   - `restore(state: Uint8Array): Promise<void>` — ripristino.
   - `getSram(): Promise<Uint8Array | null>` / `loadSram(data: Uint8Array): Promise<void>` — SRAM cartuccia.
   - Mapping per adapter: WasmBoy (`saveState`/`loadState`, cartridge RAM API), mGBA (save state + save file). `StubEngine` implementa no-op/empty (test). Capacità non supportate → metodo che rifiuta con messaggio (no claim falsi).
2. **Estendere `StoragePort`** ([[storage-port]]) con:
   - `putSaveState(romId, slot, snapshot)` / `listSaveStates(romId)` / `getSaveState(id)` / `deleteSaveState(id)`.
   - `putSram(romId, data)` / `getSram(romId)`.
   - Implementati nell'IndexedDBAdapter sugli store `saveStates`/`sram`.
3. **`SaveService` (dominio)** orchestra engine↔storage:
   - Salva: `engine.snapshot()` → `storage.putSaveState(romId, slot, blob)`.
   - Carica: `storage.getSaveState(id)` → `engine.restore(blob)`.
   - SRAM: autosave su `stop`/pausa (`engine.getSram()` → `storage.putSram`), reload su `load` (`storage.getSram` → `engine.loadSram`).
   - Export/import (US-019): serializza una entry `saveStates`/`sram` in un file portabile, versionato; import valida e riassocia al rom.
4. **UI**: pannello "Save state" nel `Player` (slot: Salva/Carica) — vedi [[schermata-player]]; sezione "Dati" in `Settings` per export/import — vedi [[schermata-settings]].

## Conseguenze

- **Positive**: salvataggi reali sfruttando le API degli emulatori; persistenza on-device coerente con ADR-002; dominio agnostico (SaveService su porte/interfacce); StubEngine mantiene unit/e2e deterministici.
- **Negative/rischi**: formato save state **specifico per emulatore/versione** (un save WasmBoy non è caricabile da mGBA e viceversa) → l'entry `saveStates` deve memorizzare `core`/`engine` e l'import validare la compatibilità; export cross-device assume stesso engine/versione.
- **Invariante**: dati solo on-device (US-033); nessun contenuto protetto.
