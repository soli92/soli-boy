# ADR-003 — Integrazione del core di emulazione (EmulatorJS)

## Contesto

Il sistema deve avviare il gioco con il core appropriato alla piattaforma riconosciuta dall'estensione e dal contenuto del file. [^src: management/kanban/EP-001-gestione-file-di-gioco/US-002-riconoscimento-piattaforma/US-002.md §Business Rules]

Deve controllare il ciclo di esecuzione (avvio, pausa, ripresa, arresto), gli input da tastiera/gamepad/touch, l'audio e, dove supportato, fast-forward/rewind. [^src: management/kanban/EP-003-esecuzione-e-controlli/US-011-pausa-ripresa-arresto/US-011.md §Business Rules]

## Decisione

Si introduce un modulo **`CoreWrapper`** (in `src/core/`) che incapsula EmulatorJS ed espone al dominio un'interfaccia stabile (vedi [[core-wrapper]]):

- **Mapping piattaforma → core**: una tabella `riconoscimento(file) → { piattaforma, core }` con Gambatte (GB/GBC), mGBA (GBA), FBNeo/MAME (arcade).
- **Lifecycle**: `load`, `start`, `pause`, `resume`, `stop`.
- **Input bridge**: tastiera, Gamepad API, controlli touch (mobile) → eventi del core; supporto rimappatura/profili (US-013).
- **Output**: rendering audio/video, controllo volume/mute (US-015), fast-forward/rewind condizionati al supporto del core (US-014).
- **Esecuzione mobile**: il core gira nel WebView del contenitore Capacitor.

## Conseguenze

- **Positive**: un solo punto di integrazione con l'emulazione; il dominio resta agnostico rispetto al core specifico; copre US-002, US-010..US-015.
- **Negative/rischi**: su iOS l'esecuzione WebAssembly passa per il WebView di sistema con limiti di JIT/prestazioni e policy App Store mutevoli — da validare (US-035, [[emulazione-su-mobile]]); rewind dipendente dal singolo core.
- **Vincolo legale**: il wrapper esegue solo file forniti dall'utente; nessun contenuto protetto incluso (US-006).
