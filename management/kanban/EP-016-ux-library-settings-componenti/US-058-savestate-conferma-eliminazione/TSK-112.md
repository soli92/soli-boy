# TSK-112 — QA: test funzionale dialog elimina SaveStatePanel

## Context

Post-implementazione TSK-111, il dialog di conferma elimina deve essere verificato
con functional oracle. Il flusso richiede un'interazione multi-step (click Elimina →
dialog aperto → click Annulla/Conferma) che i test unitari coprono ma che deve essere
verificata anche in integrazione.

Aggiornare `code_quality/acceptance/soliboy.acceptance.yaml` con uno scenario
"delete-savestate-confirm" che copre il flusso interattivo.

## Acceptance Criteria

1. Scenario `delete-savestate-confirm` aggiunto alla acceptance spec:
   - Setup: Player running con save state esistente in slot 1.
   - Step 1: click su "Elimina slot 1" → dialog modale aperto nel DOM.
   - Step 2: click "Annulla" → dialog chiuso, save state ancora presente.
   - Step 3: click "Elimina slot 1" di nuovo → dialog aperto.
   - Step 4: click "Elimina" nel dialog → save state rimosso (lista aggiornata).
2. Functional oracle eseguito: verdetto PASS su scenario delete-savestate-confirm.
3. Test a11y (run_a11y_scan) sul dialog: nessuna violation (focus trap, role dialog,
   aria-label).
4. Scenario aggiunto senza rompere gli scenari esistenti nella acceptance spec.

## DoD

- [ ] Functional oracle PASS sul nuovo scenario
