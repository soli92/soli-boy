# TSK-111 — SaveStatePanel: dialog conferma prima di eliminare save state

## Context

**UX-023:** Nel `SaveStatePanel.tsx:192-208`
(`[^src5: packages/app/src/components/Player/SaveStatePanel.tsx]`),
la funzione `handleDelete` invoca `saveService.deleteSaveState(rec.id)` immediatamente
al click sul pulsante "Elimina", senza dialog di conferma. Un tap accidentale su mobile
può cancellare ore di gioco.

Il fix: intercettare il click su "Elimina" con uno slot confirm-delete state locale.
Prima di invocare `deleteSaveState`, aprire un dialog modale di conferma.
Pattern condiviso con US-056/TSK-108 (dialog rimozione ROM) e US-053/TSK-101 (gate cambio gioco).

## Acceptance Criteria

1. Click su "Elimina" su uno slot occupato apre un dialog modale:
   - Titolo: "Eliminare save state?"
   - Body: numero/nome dello slot (es. "Slot 2") e data del save (da `rec.createdAt`
     formattata come `toLocaleString()`).
   - Pulsanti: "Annulla" (focus iniziale), "Elimina" (classe `sb-danger`).
2. Il dialog ha focus trap: Tab/Shift+Tab navigano tra i pulsanti. Esc = Annulla.
   Enter sul pulsante "Elimina" focused = conferma.
3. La conferma invoca `saveService.deleteSaveState(rec.id)`. In caso di errore,
   il dialog si chiude e il `message` state mostra `role="alert"` con messaggio di errore.
4. Click su "Elimina" su uno slot vuoto (`occupied === false`): nessun dialog (no-op,
   il pulsante è già `disabled` ma la logica di guard è esplicita).
5. Test funzionale: "click Elimina → Annulla" → save state ancora presente;
   "click Elimina → Conferma" → save state rimosso (verifica via `listSaveStates`).
