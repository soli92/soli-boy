# TSK-110 — Settings: titolo ROM in sezione Dati + accordion Resa video default open

## Context

Due finding di un liner in `Settings.tsx`:

**UX-027:** `Settings.tsx:568-575` mostra `currentRom.id.slice(0, 6)` come riferimento
al gioco corrente (`[^src5: packages/app/src/components/Settings/Settings.tsx]`).
`currentRom: RomSummary` ha già un campo `title` (riga 76-78). Basta usarlo.

**UX-028:** L'accordion "Resa video" a `Settings.tsx:442` ha `<details>` senza
attributo `open` (`[^src5: packages/app/src/components/Settings/Settings.tsx]`).
L'accordion "Controlli" a riga 400 ha `<details open>`. Basta spostare l'`open` di default
su "Resa video" e rimuoverlo da "Controlli".

L'allineamento con TSK-098 (hook `useSaveData`): se TSK-098 è completato, la sezione
dati usa il hook. In quel caso il fix del title va applicato nell'hook o nel componente
che lo riceve. Verificare dipendenza.

## Acceptance Criteria

1. La sezione dati in Settings mostra `currentRom.title` (invece di
   `currentRom.id.slice(0, 6)`) come riferimento al gioco corrente. Il testo diventa
   "Gioco corrente: [titolo]".
2. Se `currentRom` è `undefined`, mostra "Nessun gioco corrente" (testo neutro).
3. L'accordion "Resa video" ha `open` attribute di default al mount di Settings.
4. L'accordion "Controlli — rimappatura" non ha `open` attribute di default
   (resta chiuso al mount).
5. L'apertura/chiusura manuale delle accordion non viene persistita.
6. Test snapshot: stato iniziale di Settings (con `currentRom` definito) mostra titolo
   al posto dell'ID troncato. Test snapshot: accordion "Resa video" ha `open` nel DOM.

## DoD

- [ ] `currentRom.title` usato nella sezione dati al posto di `id.slice(0,6)`
- [ ] Testo "Nessun gioco corrente" se `currentRom` undefined
- [ ] Accordion "Resa video" `open` di default, "Controlli" senza `open`
- [ ] Test snapshot aggiornati
