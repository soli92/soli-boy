# TSK-166 — Fix CSS header mobile portrait + ThemeSwitcher in Settings (US-105) — P0 bloccante

## Context

Bug bloccante P0 confermato dal product owner e dall'audit (US-105): in portrait ≤640px la
navbar entra in overlay e il tab **Play** rimane nascosto sotto il logo. L'analisi root-cause
indica due cofattori nel `sb-app-header` (flex-row con `flex-wrap: wrap`):

1. **Logo** (`max-width: 200px`, `height: 40px`).
2. **ThemeSwitcher** (~198px con `white-space: nowrap`) — assorbe tutto lo spazio orizzontale
   disponibile su iPhone 375–430px e non lascia spazio al `TabsList`.

**Decisione PO (confermata):** su viewport ≤640px il `ThemeSwitcher` **sparisce dall'header**
e viene spostato **nel tab Settings** (sezione "Tema" dedicata, visibile solo su mobile via
CSS `hidden md:block` / `block md:hidden`). Su desktop (>640px) l'header rimane invariato.

Riferimenti vincolanti:
- `wiki/concepts/layout-responsive.md` — layout mobile-first.
- `wiki/concepts/controlli-touch.md` — RFM-09 (safe-area, elementi interattivi raggiungibili).
- Shell baseline EP-021: `management/kanban/EP-021-visual-fidelity-prototype/US-101-shell-prototype-parity/US-101.md`.

## Technical Specs

**Root cause (da analisi `app-extra.css` righe 67–88 + `App.tsx` righe 420–439):**

```
Header flex-row (justify-content: space-between; flex-wrap: wrap):
  [Logo ~120px]  [Nav flex:1]  [ThemeSwitcher ~198px]
Su 390px:  120 + 12 (gap) + 198 + 12 = 342px → nav residua ≈ 48px → tabs collassano / wrappano
           il wrap porta la nav sotto, ma senza reset positioning → overlay
```

**Fix P0 — due interventi atomici nello stesso TSK:**

### Intervento A — Nascondere ThemeSwitcher dall'header su mobile

**Opzione raccomandata: classe CSS + Tailwind** (nessuna modifica alla logica React):

In `App.tsx` (riga 438), avvolgere `<ThemeSwitcher>` con una classe che lo nasconde su mobile:

```tsx
{/* ThemeSwitcher nascosto su mobile (≤640px) — su mobile si trova in Settings (TSK-166) */}
<div className="hidden sm:block">
  <ThemeSwitcher theme={theme} onThemeChange={setTheme} />
</div>
```

`sm:` = breakpoint Tailwind `min-width: 640px` → il ThemeSwitcher appare solo su ≥640px.

### Intervento B — Layout header su mobile corretto

Con il ThemeSwitcher rimosso dal flex-row su mobile, la somma è:
```
[Logo ~120px] [Nav flex:1]
```
Lo spazio per la nav è ora sufficiente. Tuttavia per robustezza aggiungere anche in
`app-extra.css` la regola di sicurezza per ≤639px:

```css
@media (max-width: 639px) {
  .sb-app-header {
    flex-wrap: nowrap; /* prevent any future wrap regression */
  }
  .sb-app-header__nav {
    /* ensure tabs are fully visible and scrollable if still tight */
    overflow-x: auto;
  }
}
```

### Intervento C — ThemeSwitcher in Settings.tsx (sezione "Tema" mobile-only)

In `packages/app/src/components/Settings/Settings.tsx`, aggiungere un'`AccordionItem`
"Tema" visibile **solo su mobile** (≤639px), che contiene il `<ThemeSwitcher>`:

```tsx
{/* Sezione Tema — visibile solo su mobile (≤639px), su desktop c'è ThemeSwitcher in header */}
<div className="block sm:hidden">
  <AccordionItem value="theme">
    <AccordionTrigger>Tema</AccordionTrigger>
    <AccordionContent>
      <ThemeSwitcher theme={theme} onThemeChange={onThemeChange} />
    </AccordionContent>
  </AccordionItem>
</div>
```

**Props necessarie in Settings:** `theme` e `onThemeChange` sono già passate da `App.tsx`
(riga 542–543 — pattern già esistente in Sprint 12). Verificare che siano nel tipo
`SettingsProps` (`packages/app/src/components/Settings/Settings.tsx` — aggiungere solo
se assenti, altrimenti sono già disponibili).

**File da modificare:**
- `packages/app/src/App.tsx` — riga 438: wrap ThemeSwitcher con `<div className="hidden sm:block">`.
- `packages/app/src/styles/app-extra.css` — aggiungere `@media (max-width: 639px)` defensive rule.
- `packages/app/src/components/Settings/Settings.tsx` — aggiungere `AccordionItem` "Tema"
  con `className="block sm:hidden"`.

**Invarianti da preservare:**
- Su desktop (≥640px): layout header a riga invariato (EP-021 — US-101/103).
- Props `theme` + `onThemeChange` già presenti in `AppContent` → `Settings` → invarianti.
- `aria-label="Navigazione principale"` e `aria-label="Sezioni app"` invariati.
- Safe-area insets su `.sb-app.proto-root` invariati.
- Nessuna modifica alla logica di `useTheme` / `makeThemePort` / `ThemeSwitcher` interno.

## Implementation Steps

1. Leggere `packages/app/src/App.tsx` (riga 415–440) per confermare la struttura header.
2. Avvolgere `<ThemeSwitcher>` in `<div className="hidden sm:block">` (Intervento A).
3. Aggiungere regola `@media (max-width: 639px)` in `app-extra.css` (Intervento B).
4. Leggere `packages/app/src/components/Settings/Settings.tsx` per identificare la struttura
   dell'`Accordion` e le props disponibili.
5. Aggiungere l'`AccordionItem` "Tema" in `Settings.tsx` con `className="block sm:hidden"`
   (Intervento C).
6. `npm run build` verde — nessun errore TypeScript.
7. Verificare visivamente in DevTools su 390px: header mostra solo logo + tabs; ThemeSwitcher
   assente dall'header.
8. Verificare su ≥640px: header con logo + tabs + ThemeSwitcher (invariante desktop).
9. Verificare in tab Settings su mobile: accordion "Tema" visibile con ThemeSwitcher funzionante.
