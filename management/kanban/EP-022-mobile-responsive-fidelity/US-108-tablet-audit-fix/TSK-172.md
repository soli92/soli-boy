# TSK-172 — Fix layout tablet (US-108)

## Context

Fix dei delta classificati "blocker" o "major" per il viewport **tablet (~768px)** identificati
dall'audit US-104 (TSK-165). L'app non ha mai avuto breakpoint Tailwind esplicitamente calibrati
sul breakpoint tablet intermedio: il layout attuale cade nel desktop (perché 768px ≥ 640px) ma
non ha ancora i layout a colonne previsti dal design brief. [^src: US-108, EP-022]

Riferimenti vincolanti:
- `wiki/concepts/layout-responsive.md` §Adattamenti per sezione — layout attesi:
  - Library: **3 colonne** su tablet.
  - Settings: sezioni in **2 colonne**; sezione "Dati" full-width.
  - Player: layout verticale con TouchOverlay (analogo mobile, ma più spazio).
- `wiki/entities/schermata-library.md`, `wiki/entities/schermata-settings.md`,
  `wiki/entities/schermata-player.md`.
- Design brief: `wiki/design/ep020-design-brief.md` §5 (invariante `.sb-screen`).

**Nota:** i delta esatti emergeranno dal report TSK-165 sezione "Tablet". La specifica tecnica
descrive le aree candidate basandosi sull'analisi del codice.

## Technical Specs

**Breakpoint tablet target:** `min-width: 640px` e `max-width: 1023px` (o equivalente
Tailwind `sm:` senza `lg:`). Il breakpoint Tailwind `md: 768px` è il riferimento principale.

**File candidate per il fix:**

1. `packages/app/src/components/Library/Library.tsx` — la griglia di GameTile.
   Attualmente usa Tailwind grid utility (introdotto da TSK-146). Verificare se la classe
   grid ha il breakpoint tablet: `grid-cols-2 sm:grid-cols-3 lg:grid-cols-5` (o simile).
   Il target è **3 colonne su tablet** (768px), quindi assicurarsi che `md:grid-cols-3` sia
   presente.

2. `packages/app/src/components/Settings/Settings.tsx` — le sezioni dell'Accordion.
   Attualmente le sezioni sono in colonna singola. Aggiungere un layout a 2 colonne per
   tablet: wrapper `grid grid-cols-1 md:grid-cols-2 gap-4` attorno agli `AccordionItem`,
   con la sezione "Dati" (slot dedicato) in `col-span-2` (full-width).

3. `packages/app/src/styles/app-extra.css` — `.sb-play-row` (righe 154–165).
   Il `.sb-play-row` attiva la sidebar con `@media (min-width: 768px)`: su tablet portrait
   (~768px width) la sidebar appare. Valutare se la sidebar desktop è appropriata anche su
   tablet portrait (768px), o se restringere a `min-width: 1024px` (già valutato in TSK-170
   per landscape). Coordinare la decisione con quanto fatto in TSK-170.

**Invarianti da preservare:**
- `.sb-screen` aspect-ratio e safe-area (invariante EP-020 §5).
- Navbar tab accessibile (non sovrapposta al logo — analoga garanzia US-105).
- Sezione "Info & Privacy" mantiene il layout definito in EP-021 (US-102).
- I marker DOM EP-021 (`proto-root`, `theme-switcher`, `sb-privacy-section`, `sb-legal-card`)
  restano stabili.

## Implementation Steps

1. Leggere il report `code_quality/reports/EP-022-fidelity-audit.md` (TSK-165) — sezione
   "Tablet" — per la lista definitiva dei delta blocker/major.
2. Per ogni delta blocker/major:
   a. Identificare il componente / file CSS responsabile.
   b. Applicare il breakpoint Tailwind corretto (target `md: 768px`).
3. Library: verificare e aggiornare la classe grid in `Library.tsx` per avere `md:grid-cols-3`.
4. Settings: aggiungere layout a griglia 2 colonne sul wrapper delle sezioni (tablet only).
5. `.sb-play-row`: decidere se restringere il breakpoint sidebar a `lg: 1024px` (coordinare
   con quanto applicato in TSK-170 per mobile landscape).
6. Verificare navbar non sovrapposta al logo su 768px (invariante US-105 — fix TSK-166 già attivo).
7. `npm run build` verde.
