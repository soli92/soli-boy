# TSK-169 — Implementazione SVG logo nel codice (US-106)

## Context

Sblocca dopo TSK-168 (gate umano: designer produce i 4 SVG). Questo task sostituisce nel codice
gli asset logo precedenti con le nuove varianti SVG prodotte in TSK-168 e verifica il rendering
in-app su entrambi i temi e nei viewport mobile/desktop. [^src: US-106]

**Asset correnti da sostituire:**
- `packages/app/src/assets/soliboy-logo-horizontal.svg` — importato in `App.tsx` (riga 4:
  `import logoUrl from "./assets/soliboy-logo-horizontal.svg"`)
- Favicon e icon eventualmente in `packages/app/public/` (verificare `index.html` per i link tag
  introdotti da TSK-043/045).

## Technical Specs

**File da modificare / creare:**

1. `packages/app/public/logo/` — cartella di destinazione (creata da TSK-168).
   - Verificare che i 4 file SVG prodotti in TSK-168 siano presenti.

2. `packages/app/src/App.tsx` (riga 4):
   - Aggiornare l'import di `logoUrl` per puntare alla nuova variante horizontal:
     ```ts
     // Prima:
     import logoUrl from "./assets/soliboy-logo-horizontal.svg";
     // Dopo (path da adattare alla nuova cartella):
     import logoUrl from "../../../public/logo/soliboy-logo-horizontal.svg";
     // oppure copiare in src/assets/ per uniformità con Vite asset pipeline:
     import logoUrl from "./assets/logo/soliboy-logo-horizontal.svg";
     ```
   - Valutare se è preferibile copiare gli SVG anche in `src/assets/logo/` (risoluzione Vite
     più affidabile in build) vs tenerli in `public/logo/` (serviti staticamente).

3. `packages/app/index.html` — aggiornare i link tag favicon se il path del favicon è cambiato
   (TSK-043 aveva introdotto `<link rel="icon" href="/soliboy-favicon.svg">`):
   - Aggiornare a `href="/logo/soliboy-favicon.svg"` se il file è in `public/logo/`.

4. `packages/app/public/site.webmanifest` — aggiornare i path degli icon se necessario
   (TSK-045 aveva introdotto il manifest).

**Verifica rendering richiesta:**
- Rendering `soliboy-logo-horizontal.svg` nell'`<img className="sb-logo">` di `App.tsx`
  (riga 422): verificare che l'immagine si carichi correttamente e rispetti i CSS
  `.sb-logo { display: block; height: 40px; width: auto; max-width: 200px; }` (solids-theme.css).
- Nessun overlay o overflow che riacuisca il bug US-105 (invariante R.D3 non-regressione).
- Rendering del favicon nel browser tab.

**Screenshot di verifica** (da salvare in `code_quality/reports/EP-022-logo-revision/`):

- Logo su viewport desktop in tema 90s-party.

- Favicon nel browser tab (se catturabile).

## Implementation Steps

1. Verificare contenuto di `packages/app/public/logo/` (TSK-168 deve essere `done`).
2. Decidere strategia path (copiare in `src/assets/logo/` vs importare da `public/logo/`);
   preferire `src/assets/logo/` per compatibilità Vite build.
3. Aggiornare l'import in `App.tsx` riga 4.
4. Aggiornare `index.html` favicon link se path cambiato.
5. Aggiornare `site.webmanifest` icon paths se necessario.
6. `npm run build` in `packages/app` — verificare build verde senza warning asset.
7. `npm run preview` — verificare visivamente logo e favicon nel browser.
8. Salvare screenshot in `code_quality/reports/EP-022-logo-revision/`.
