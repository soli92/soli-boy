# TSK-165 — Audit visivo prototipo↔produzione (US-104)

## Context

EP-022 dipende da EP-020 (migrazione Solids) ed EP-021 (parità desktop). Il product owner ha
segnalato delta visivi sistematici su viewport non-desktop mai auditati. Questo task produce il
report di audit che è l'**input autoritativo** per i fix di Wave B (US-107/108/109). Il task è
**read-only** sul codice: non modifica sorgenti. [^src: US-104, EP-022]

Riferimento vincolante: `wiki/design/ep020-design-brief.md` (R.D1). Prototipo di riferimento:
`output/prototypes/ep020/`. Baseline visual oracle EP-021: `code_quality/reports/EP-021-visual-oracle.md`.

## Technical Specs

**Tool:** visual-oracle headless (Playwright) già configurato in `packages/app`.

**Viewport target** (coerenti con `wiki/concepts/layout-responsive.md`):
- Mobile portrait: `{ width: 390, height: 844 }`
- Mobile landscape: `{ width: 844, height: 390 }`
- Tablet: `{ width: 768, height: 1024 }`
- Desktop: `{ width: 1280, height: 800 }`

**Tab target:** Play, Library (Libreria), Settings (Impostazioni), Info & Privacy

**Temi:** `cyberpunk`, `90s-party`

**Matrice:** 4 viewport × 4 tab × 2 temi = **32 combinazioni** di screenshot.

**File prodotti:**
- Report: `code_quality/reports/EP-022-fidelity-audit.md`
- Screenshot: `code_quality/reports/EP-022-fidelity-audit/` (struttura: `<viewport>-<tab>-<tema>.png`)

**Struttura report (sezioni obbligatorie):**

```

  ### Tab Play — cyberpunk | 90s-party
  ### Tab Library — cyberpunk | 90s-party

  ### Tab Info — cyberpunk | 90s-party

  [stessa struttura]
## Tablet (~768px)
  [stessa struttura]
## Desktop (~1280px)
  [stessa struttura]

```

**Classificazione delta:**
- Severità: `blocker` | `major` | `minor` | `cosmetic`
- Area: `layout` | `spacing` | `tipografia` | `colore` | `componente` | `iconografia`

I delta già noti (navbar mobile portrait overlay + Play tab nascosto) devono essere **confermati o
smentiti** in questa audit e marcati con severità `blocker` se confermati — ma la risoluzione è US-105.

## Implementation Steps

1. Configurare Playwright per i 4 viewport (aggiungere configuration o usare il flag `--project`
   con i viewport esistenti in `packages/app/playwright.config.ts`).
2. Per ogni combinazione viewport×tab×tema:
   a. Navigare l'app (porta `:4173` o `preview`).
   b. Applicare il tema via `data-theme` attribute su `<html>`.
   c. Navigare alla tab target.
   d. Screenshot full-page salvato in `code_quality/reports/EP-022-fidelity-audit/`.
3. Confrontare side-by-side con il prototipo `output/prototypes/ep020/` (visione LLM multimodale).
4. Per ogni delta: annotare descrizione, severità, area, viewport, tab, tema, link screenshot.
5. Compilare la sezione "Checklist raccomandazioni" raggruppata per viewport.
6. Salvare il report in `code_quality/reports/EP-022-fidelity-audit.md`.
