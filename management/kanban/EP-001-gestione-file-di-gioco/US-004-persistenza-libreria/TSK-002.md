# TSK-002 — StoragePort + dominio persistenza ROM

## Context
Il dominio deve persistere e recuperare le ROM tramite una porta astratta, indipendente dal meccanismo di storage. [^src: management/kanban/EP-001-gestione-file-di-gioco/US-001-caricare-rom/US-001.md §Acceptance Criteria]

## Technical Specs
- **BE:** interfaccia `StoragePort` con `addRom` / `listRoms` / `getRom` / `removeRom` come da [storage-port](../../../../design_&_architecture/api_specs/storage-port.md).
- **Decisione:** [ADR-002](../../../../design_&_architecture/decisions/ADR-002.md) — adapter IndexedDB (TSK-001) dietro la porta.
- Associazione ROM → metadati (titolo, piattaforma, core).

## Implementation Steps
1. Definire l'interfaccia `StoragePort` (operazioni su `roms`).
2. Collegare l'IndexedDBAdapter (TSK-001) come implementazione.
3. Esporre al dominio `addRom`/`listRoms`/`getRom`/`removeRom`.

## Definition of Done
- [ ] Test unitario su `StoragePort` (adapter IndexedDB) passa
- [ ] Una ROM aggiunta è recuperabile da `listRoms`/`getRom`
- [ ] Code review approvata

## Dependencies
- TSK-001 — definisce l'object store sottostante
