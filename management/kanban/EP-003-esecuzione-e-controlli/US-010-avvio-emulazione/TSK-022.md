# TSK-022 — Player mount DOM + selezione engine (stub ↔ reale)

## Context
EmulatorJS si monta in un nodo DOM; il Player deve fornire il container all'engine, e l'App deve poter selezionare StubEngine (test/dev) o EmulatorJsEngine (reale). [^src: management/kanban/EP-003-esecuzione-e-controlli/US-010-avvio-emulazione/US-010.md §Acceptance Criteria]

## Technical Specs
- **fe:** il `Player` espone un container ref e lo passa all'engine (estensione minima dell'interfaccia: `LoadOptions.container?` o `mount(el)`), come da [ADR-004](../../../../design_&_architecture/decisions/ADR-004.md).
- **App:** selezione engine (StubEngine di default in test/dev; EmulatorJsEngine in produzione). Con engine reale, **disattivare** il wiring globale keydown (input gestito nativamente da EJS; InputMapping resta per touch).
- StubEngine ignora il container (compat test).

## Implementation Steps
1. Aggiungere il container/mount all'interfaccia + StubEngine no-op.
2. Player passa il nodo all'engine in `load`.
3. App: factory di selezione engine + disattiva keydown globale con engine reale.

## Definition of Done
- [ ] Player monta EmulatorJsEngine nel container; StubEngine resta compatibile
- [ ] Unit/e2e con StubEngine ancora verdi (nessuna regressione)
- [ ] Typecheck OK · review approvata
