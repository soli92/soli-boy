# TSK-021 — EmulatorJsEngine: adapter EmulatorJS reale

## Context
L'app usa StubEngine; serve l'adapter reale che esegue le ROM via EmulatorJS, dietro l'interfaccia `EmulatorEngine`. [^src: management/kanban/EP-003-esecuzione-e-controlli/US-010-avvio-emulazione/US-010.md §Acceptance Criteria]

## Technical Specs
- **core:** `EmulatorJsEngine implements EmulatorEngine` come da [ADR-004](../../../../design_&_architecture/decisions/ADR-004.md).
- Loading lazy del loader EmulatorJS (script injection una volta) + config globali `EJS_*` (`EJS_player`, `EJS_core`, `EJS_gameUrl` da Object URL del blob, `EJS_pathtodata`, `EJS_startOnLoaded`).
- Mapping interface→EJS: `load`/`start`/`pause`/`resume`/`stop` (teardown + revoke Object URL), `setAudio`, `setSpeed` (fast-forward; rewind via `capabilities`).
- `sendInput` per controlli touch (input nativo EJS per tastiera/gamepad).
- `EJS_core` da mapping piattaforma (vedi [emulatorjs-hosting](../../../../wiki/runbooks/emulatorjs-hosting.md)).

## Implementation Steps
1. Loader lazy + set globali `EJS_*`.
2. Implementare lifecycle/audio/speed sull'istanza `EJS_emulator`.
3. Teardown pulito (destroy + `URL.revokeObjectURL`).
4. Esporre `capabilities.rewind` per core.

## Definition of Done
- [ ] `EmulatorJsEngine` implementa l'interfaccia `EmulatorEngine`
- [ ] Avvio di una ROM homebrew reale verificato (vedi TSK-024)
- [ ] Nessun leak di Object URL allo stop
- [ ] Typecheck OK · review approvata
