# TSK-023 — Hosting core EmulatorJS + header COOP/COEP

## Context
I core WASM threaded richiedono COOP/COEP; l'hosting è CDN su web e self-host su desktop/mobile per l'offline (RF-24). [^src: management/kanban/EP-003-esecuzione-e-controlli/US-010-avvio-emulazione/US-010.md §Acceptance Criteria]

## Technical Specs
- **infra:** `EJS_pathtodata` → CDN (versione pinnata) su web; core vendati localmente su desktop/Capacitor. Vedi [emulatorjs-hosting](../../../../wiki/runbooks/emulatorjs-hosting.md).
- Header `Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp` nel dev server Vite (`server.headers`) e in prod.
- `consumer: human`: scelte di hosting/sicurezza/CDN-pinning richiedono supervisione umana (routing.infra: human).

## Implementation Steps
1. Configurare gli header COOP/COEP nel dev/preview Vite.
2. Pinnare la versione CDN EmulatorJS (web).
3. Predisporre il vendoring dei core per desktop/mobile (offline).

## Definition of Done
- [ ] Dev server isolato cross-origin (SharedArrayBuffer disponibile)
- [ ] `EJS_pathtodata` corretto per web e per build offline
- [ ] Documentazione hosting aggiornata nel runbook

## Dependencies
- TSK-021 — l'adapter consuma `EJS_pathtodata`
