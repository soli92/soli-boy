# TSK-095 — Fix stale closure handleCapacitorUri in FileLoader.tsx

## Context

`FileLoader.tsx:93-104` registra `handleCapacitorUri` con deps array `[]`
(`[^src5: packages/app/src/components/FileLoader/FileLoader.tsx:93]`).
Questo significa che `storage`, `onImported`, `_filesystemApi` sono catturati come
stale closure: se cambiano dopo il mount (hot-reload, test con props diverse, cambio
dell'adapter di storage), il handler registrato continua a usare i valori obsoleti.

Finding: P1-04 (major, conf. 0.90) da `soliboy-code-review-deep.md`.

Pattern di fix: usare `useRef` per mantenere una reference stabile al handler, con
un effetto separato che aggiorna il ref quando le dipendenze cambiano. In questo modo
il listener Capacitor registrato al mount chiama sempre il handler più recente
senza ri-registrare il listener.

## Acceptance Criteria

1. Il listener `handleCapacitorUri` è registrato tramite pattern stabile (useRef +
   inner function che legge dal ref) oppure tramite `useCallback` con deps complete
   correttamente dichiarate.
2. Un cambio della prop `storage` o `onImported` dopo il mount aggiorna il handler
   attivo senza ri-registrare il listener Capacitor (nessun listener duplicato).
3. Il lint rule `react-hooks/exhaustive-deps` non segnala warning sulla chiamata
   modificata (se il progetto ha il plugin ESLint hooks).
4. Test di regressione: React Strict Mode double-mount di FileLoader con mock di
   `storage` che cambia → nessun handler stale (il secondo mock è usato).
5. Tutti i test esistenti di FileLoader passano senza modifiche.

## DoD

- [ ] Test di regressione stale closure aggiunto
