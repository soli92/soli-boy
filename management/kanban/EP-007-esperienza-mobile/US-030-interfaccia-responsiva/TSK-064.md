# TSK-064 — Layout responsivo mobile: orientamento + safe areas (CSS env(), solids)

## Context

US-030 richiede un'interfaccia responsiva per portrait e landscape, rispettando le aree
sicure (notch, barre di sistema) su Android e iOS. La SPA usa già token solids e Vite;
il `TouchOverlay` (TSK-060) va adattato per entrambi gli orientamenti. [^src: management/kanban/EP-007-esperienza-mobile/US-030-interfaccia-responsiva/US-030.md §Business Rules]

## Technical Specs

- **Safe areas**: aggiungere `<meta name="viewport" content="... viewport-fit=cover">` in
  `index.html` e usare CSS `env(safe-area-inset-*)` per il padding di contenitori globali
  (header, footer, overlay).
- **Orientamento portrait**: layout verticale — Player in alto, `TouchOverlay` sotto.
- **Orientamento landscape**: Player espanso (aspect ratio preservato), `TouchOverlay`
  ai lati (D-pad a sinistra, pulsanti a destra).
- Breakpoint gestito con `@media (orientation: landscape)` e token solids per spacing.
- `TouchOverlay` riposizionato dinamicamente via classi CSS condizionali.
- Nessun elemento interattivo coperto da notch/status bar (verificare con variabili CSS
  `safe-area-inset-top/right/bottom/left`).
- Conforme al design system solids (vincolo raw/tech_stack.md).

## Implementation Steps

1. Aggiornare `index.html`: `viewport-fit=cover`.
2. Aggiungere classi CSS globali con `env(safe-area-inset-*)` nel CSS principale.
3. Aggiornare `Player.tsx` e `TouchOverlay.tsx` per il layout landscape.
4. Media query `@media (orientation: landscape)` nel CSS del `TouchOverlay`.
5. Unit test: render con `matchMedia` mockato → classi CSS applicate correttamente.
6. Smoke test visivo su emulatore (umano): rotazione → nessun overlap notch/barre.

## DoD

- [ ] L'interfaccia si adatta a portrait e landscape senza overlap.
- [ ] Nessun elemento interattivo coperto da notch/barre di sistema.
- [ ] Safe area inset applicati su Android e iOS.
- [ ] Uso esclusivo di token solids per spacing e layout.
- [ ] Build typecheck + unit test verdi.
