# TSK-061 — TouchOverlay: configurazione posizione, dimensione e opacità (persistita)

## Context

US-027 richiede che i controlli touch siano configurabili per posizione, dimensione e
opacità, con persistenza tra le sessioni. Lo store `config` (IndexedDB / NativeFs)
gestisce già preferenze per chiave/valore — `getConfig`/`setConfig` sono nel contratto
`StoragePort`. [^src: design_&_architecture/api_specs/storage-port.md §Operazioni]

## Technical Specs

- Aggiungere al `TouchOverlay` un pulsante "Configura overlay" (attivo solo in modalità
  non-game oppure long-press).
- Parametri configurabili:
  - Posizione: offset X/Y del D-pad e del blocco pulsanti (drag & drop o slider UI).
  - Dimensione: scala globale dell'overlay (S/M/L o slider 50%–150%).
  - Opacità: slider 20%–100%.
- Persistenza: salvataggio via `StoragePort.setConfig('touch-overlay', JSON.stringify(cfg))`.
- Ricaricamento: al mount del `TouchOverlay`, leggere la config salvata e applicarla.
- CSS: le variabili di posizione/dimensione/opacità sono applicate come CSS custom properties
  sul container overlay, usando token solids.

## Implementation Steps

1. Aggiungere stato `overlayConfig` nel `TouchOverlay` (o hook `useTouchOverlayConfig`).
2. UI di configurazione: pannello/drawer con slider per le tre proprietà.
3. Al cambio → CSS custom property aggiornata in real-time.
4. Al salvataggio → `storage.setConfig('touch-overlay', ...)`.
5. Al mount → leggere `storage.getConfig('touch-overlay')` e applicare.
6. Unit test: cambio config → `setConfig` chiamato; mount → `getConfig` chiamato.

## DoD

- [ ] Posizione, dimensione e opacità sono modificabili dall'utente.
- [ ] La configurazione è persistita in `config` store e riapplicata al riavvio.
- [ ] UI di configurazione usa token solids (no stili hard-coded).
- [ ] Build typecheck + unit test verdi.

## Dependencies

- TSK-001/TSK-002 (`IndexedDBAdapter`/`StoragePort` — già implementati).
