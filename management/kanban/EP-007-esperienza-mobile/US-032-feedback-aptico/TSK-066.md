# TSK-066 — Feedback aptico: vibrazione opzionale sugli input touch (Capacitor Haptics)

## Context

US-032 richiede feedback aptico opzionale sugli input touch, con toggle persistito.
Il plugin `@capacitor/haptics` è installato in TSK-059. Lo store `config` già supporta
preferenze persistite (getConfig/setConfig). [^src: management/kanban/EP-007-esperienza-mobile/US-032-feedback-aptico/US-032.md §Business Rules]

## Technical Specs

- Utilizzare `Haptics.impact({ style: ImpactStyle.Light })` da `@capacitor/haptics`
  a ogni `touchstart` sui controlli del `TouchOverlay`.
- Fallback silenzioso su browser (no Capacitor): `Haptics.impact` no-op.
- Toggle "Feedback aptico" in Settings (bool, default true).
- Persistenza: `StoragePort.setConfig('haptics-enabled', 'true'/'false')`.
- Al mount del `TouchOverlay`: leggere la preferenza e attivare/disattivare.

## Implementation Steps

1. Creare hook `useHaptics(enabled: boolean)` che espone `triggerImpact()`.
2. In `TouchOverlay`: chiamare `triggerImpact()` su ogni `touchstart`.
3. Aggiungere toggle "Feedback aptico" nella sezione Settings Mobile.
4. Persistere la preferenza via `StoragePort.setConfig`.
5. Unit test: mock `Haptics.impact` → `triggerImpact()` chiamato quando `enabled=true`;
   non chiamato quando `enabled=false`.

## DoD

- [ ] Con haptics abilitati, ogni touch sui controlli produce una vibrazione.
- [ ] Con haptics disabilitati, nessuna vibrazione.
- [ ] L'impostazione è persistita tra le sessioni.
- [ ] Nessun errore su browser (fallback silenzioso).
- [ ] Build typecheck + unit test verdi.

## Dependencies

- TSK-059 (`@capacitor/haptics` installato).
- TSK-060 (`TouchOverlay`).
