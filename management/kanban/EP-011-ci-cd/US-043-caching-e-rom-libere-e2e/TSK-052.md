# TSK-052 — Cache Playwright browser + artefatti e2e nel workflow CI (US-043)

## Context

US-043 richiede che la pipeline CI riusi una cache tra esecuzioni (npm già coperta
da TSK-049 via `actions/setup-node`) e aggiunga cache per i browser Playwright e
la pubblicazione degli artefatti e2e (report/screenshot in caso di failure). Le
ROM libere MIT in `packages/app/public/test-roms/` eliminano download esterni. [^src: management/kanban/EP-011-ci-cd/US-043-caching-e-rom-libere-e2e/US-043.md §Business Rules]

**Decisioni di prodotto incorporate:**
- Cache npm: gestita da `actions/setup-node` in TSK-049 (già presente)
- Cache browser Playwright: `actions/cache` su `~/.cache/ms-playwright`
- ROM e2e: solo quelle MIT già versionate in `public/test-roms/` (dmg-acid2.gb,
  gba-tests-thumb.gba) — nessun download esterno
- Artefatti pubblicati: report Playwright (`playwright-report/`) su failure

## Technical Specs

Questo task modifica `.github/workflows/ci.yml` introdotto da TSK-049. Le
modifiche sono additive (non cambiano la struttura esistente).

### 1. Cache browser Playwright

Aggiungere uno step prima di `npx playwright install`:

```yaml
      - name: Cache Playwright browsers
        uses: actions/cache@v4
        id: playwright-cache
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ hashFiles('packages/app/package-lock.json') }}
          restore-keys: |
            playwright-${{ runner.os }}-

      - name: Install Playwright browsers (Chromium only)
        if: steps.playwright-cache.outputs.cache-hit != 'true'
        run: npx playwright install --with-deps chromium
```

**Nota:** se la cache è un hit, il `--with-deps` installa le system deps (libglib,
libnss, ecc.) ma salta il download dei browser. In alternativa semplificata,
eseguire comunque `npx playwright install chromium` (senza `--with-deps`) se la
cache è presente ma le deps di sistema non sono cachate. L'approccio con `if`
riduce il tempo sulla cache hit.

**Assunzione annotata:** su `ubuntu-latest` le system deps per Chromium sono
incluse nel runner di base. Se il job fallisce con "Missing system deps" su
cache hit, rimuovere la condizione `if` e fare sempre `npx playwright install
chromium` (il binario è cachato, le deps no — trade-off accettabile).

### 2. Artefatti e2e su failure

Aggiungere dopo lo step e2e:

```yaml
      - name: Upload Playwright report (solo su failure)
        uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: playwright-report
          path: packages/app/playwright-report/
          retention-days: 7
```

La directory `playwright-report/` è quella default di Playwright (output HTML
reporter). Per abilitare il report HTML in CI, aggiungere alla `reporter` config
di `playwright.config.ts` la stringa `"html"` quando `process.env.CI` è truthy,
oppure impostare `reporter: [["line"], ["html"]]` per CI. In alternativa usare
`--reporter=html` nel comando `npm run e2e` (override via argomento).

**Assunzione annotata:** `playwright.config.ts` usa `reporter: "line"` in CI.
Per raccogliere artefatti HTML bisogna attivare il reporter HTML. La modifica
più semplice è passare `--reporter=html` nell'invocazione npm run e2e (script
`package.json`) solo in CI: `npm run e2e -- --reporter=html`. Oppure modificare
`playwright.config.ts` per aggiungere `"html"` quando `process.env.CI`. Il TSK
lascia la scelta all'implementatore (entrambe le opzioni portano allo stesso risultato).

### 3. Verifica ROM libere (nessuna modifica richiesta)

Le ROM MIT in `packages/app/public/test-roms/` sono già nel repo e versionate. Il
workflow le include automaticamente tramite `actions/checkout@v4`. Nessun step
aggiuntivo necessario. Questa è la garanzia dell'AC "nessun download di ROM/BIOS
esterni durante il job". [^src: management/kanban/EP-011-ci-cd/US-043-caching-e-rom-libere-e2e/US-043.md §Business Rules]
