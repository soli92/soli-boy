# TSK-050 — Branch protection `main`: gate CI obbligatorio (US-041)

## Context

US-041 richiede che la branch `main` sia protetta: PR obbligatoria, status check
CI verde richiesto prima del merge, no force-push, no cancellazione del branch.
Le decisioni di prodotto ratificate chiudono il gap `branch-protection-policy`. [^src: management/kanban/EP-011-ci-cd/US-041-branch-protection/US-041.md §Business Rules]

**Nota consumer:** questo task è `consumer: human` perché la CONFIGURAZIONE effettiva
delle branch protection rules su GitHub è un gate umano (R.14 VCS gate, R.15
cross-tool publish gate). Il TSK descrive la configurazione da applicare e fornisce
i comandi `gh` come guida, ma l'esecuzione effettiva è a cura dell'owner. [^src: CLAUDE.md §Vincoli inviolabili]

**Decisioni di prodotto incorporate (ratificate dall'owner):**
- Status check obbligatorio: job `ci` del workflow `CI` (TSK-049)
- Nessuna review obbligatoria (repo single-committer)
- No force-push su `main`
- No cancellazione del branch `main`
- PR obbligatoria per merge su `main`

## Technical Specs

### Configurazione da applicare su GitHub

Via GitHub UI (Settings → Branches → Add rule) o via `gh` CLI:

```bash
# Prerequisito: gh auth login
# Crea la branch protection rule su main
gh api \
  --method PUT \
  -H "Accept: application/vnd.github+json" \
  /repos/soli92/soli-boy/branches/main/protection \
  --input - <<'EOF'
{
  "required_status_checks": {
    "strict": true,
    "contexts": ["ci"]
  },
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null,
  "allow_force_pushes": false,
  "allow_deletions": false,
  "block_creations": false
}
EOF
```

**Parametri chiave:**
- `"contexts": ["ci"]` — nome del job nel workflow `ci.yml` (TSK-049). Se il job
  si chiama diversamente nel YAML, aggiornare il context.
- `"required_pull_request_reviews": null` — nessuna review richiesta (singolo
  committer, ratificato).
- `"allow_force_pushes": false` — blocca force-push su main.
- `"allow_deletions": false` — blocca cancellazione del branch.
- `"enforce_admins": false` — non impone le regole all'admin (flessibilità per
  emergenze di un repo single-owner; l'owner può impostare `true` se preferisce
  la massima rigidità).

**Assunzione annotata:** `"enforce_admins": false` è il default meno restrittivo
per un repo single-committer. Se l'owner vuole enforcement totale (anche admin),
cambiare a `true` nel comando sopra.

### Verifica post-applicazione

Dopo aver applicato la regola, verificare:
```bash
gh api /repos/soli92/soli-boy/branches/main/protection | jq .
```

Atteso: `required_status_checks.contexts` contiene `"ci"`.
