# TSK-049 — Workflow CI GitHub Actions: ci.yml (US-040)

## Context

US-040 richiede una pipeline CI che si attivi su push e pull request verso `main`,
eseguendo typecheck, unit test, e2e e build. Le decisioni di prodotto ratificate
chiudono i gap `ci-cd-pipeline-definition` per il workflow CI. [^src: management/kanban/EP-011-ci-cd/US-040-pipeline-ci-github-actions/US-040.md §Business Rules]

**Decisioni di prodotto incorporate (ratificate dall'owner):**
- Piattaforma: GitHub Actions
- File: `.github/workflows/ci.yml`
- Trigger: `push` e `pull_request` verso `main`
- Runner: `ubuntu-latest`
- Node: 20 LTS
- Steps: checkout → setup-node (cache npm) → `npm ci` → typecheck → unit → install
  browser Playwright (solo chromium) → e2e (chromium) → build
- Working directory: `packages/app` (monorepo)
- ROM e2e: MIT già in `packages/app/public/test-roms/` (no download esterno)
- Headers COOP/COEP: già nel webServer Vite (playwright.config.ts) — nessuna
  modifica richiesta al config

## Technical Specs

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  ci:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: packages/app

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node 20
        uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: "npm"
          cache-dependency-path: packages/app/package-lock.json

      - name: Install dependencies
        run: npm ci

      - name: Typecheck
        run: npm run typecheck

      - name: Unit tests (Vitest)
        run: npm test

      - name: Install Playwright browsers (Chromium only)
        run: npx playwright install --with-deps chromium

      - name: E2e tests (Playwright / Chromium)
        run: npm run e2e

      - name: Build
        run: npm run build
```

**Note implementative:**
- `cache-dependency-path` punta al `package-lock.json` di `packages/app`
  (monorepo: non c'è un lock file a root).
- `npm ci` (non `npm install`): deterministico e più veloce in CI.
- L'e2e usa il webServer Vite dichiarato in `playwright.config.ts`
  (`reuseExistingServer: !process.env.CI` → in CI viene avviato fresco).
- Il job non ha `env: REAL_ENGINE=...` → App usa StubEngine in e2e (default
  già presente in App.tsx, safe). I test e2e `emulation-real.e2e.ts` e
  `emulation-gba.e2e.ts` usano `?engine=real` via URL: verificare che il CI
  li esegua correttamente. Se falliscono per timing in headless, aggiungere
  `retries: 2` (già nel playwright.config.ts per `CI=true`).

**Assunzione annotata:** i test e2e `emulation-real.e2e.ts` e `emulation-gba.e2e.ts`
richiedono l'engine reale (WasmBoy/mGBA) con le ROM MIT in `public/test-roms/`.
Il workflow non imposta `REAL_ENGINE` ma Playwright passa le URL con `?engine=real`
definite nelle spec stesse. Se in ambiente CI i test real-engine sono instabili
per timeout WASM, si può aggiungere una timeout estesa o isolarli in un job
separato — da decidere in prima esecuzione (non blocca la definizione del workflow).
