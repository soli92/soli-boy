# US-040 — Pipeline CI su GitHub Actions (typecheck, unit, e2e, build)

## Descrizione
Come maintainer di Soli-boy, voglio che ogni push e ogni pull request scateni automaticamente una pipeline di Continuous Integration che verifica la salute del codice (tipizzazione, test unitari, test end-to-end, build di produzione), affinché le regressioni siano intercettate prima del merge.

## Business Rules
- Lo stack del prodotto include TypeScript (tipizzazione), React + Vite (build), Vitest (test unitari), Playwright (test end-to-end). [^src: wiki/syntheses/stack-tecnologico-soli-boy.md §Panoramica dello stack]
- La pipeline deve coprire almeno: installazione dipendenze, typecheck, test unitari (Vitest), test end-to-end (Playwright in Chromium), build di produzione (Vite).
- I trigger della pipeline sono push e pull request (la pipeline è il prerequisito tecnico al gate di qualità di US-041).
- I dettagli operativi (matrice OS/Node, runner, action specifiche, parallelismo) sono fuori dallo scope di prodotto: sono tracciati come gap non-bloccante `ci-cd-pipeline-definition` su `wiki/gaps.md` da risolvere in design/architettura.

## Acceptance Criteria
- [ ] Il repository contiene almeno un workflow di Continuous Integration che si attiva automaticamente su push e su apertura/aggiornamento di pull request.
- [ ] Il workflow installa le dipendenze, esegue la tipizzazione, esegue i test unitari con Vitest, esegue i test end-to-end con Playwright (Chromium) e produce la build di produzione del frontend.
- [ ] L'esito della pipeline (verde/rosso) è visibile sulla pull request prima del merge.
- [ ] In caso di fallimento di una qualunque fase, il workflow termina in stato di fallimento e l'esito è propagato come status check del commit.
