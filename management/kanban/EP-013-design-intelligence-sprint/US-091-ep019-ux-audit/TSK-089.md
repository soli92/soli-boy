# TSK-089 — Design token audit: verifica usage SoliDS in soli-boy

## Context

soli-boy usa `@soli92/solids` (token-based design system). Il package è bloccato (TSK-040 blocked su Q_001
— npm 404, github senza dist), ma i token CSS sono presenti nel file locale `src/styles/solids-theme.css`.

Questo TSK documenta:
1. Quali token SoliDS sono attualmente usati nel codice (grep nelle classi sd-* e css custom props --sd-*)
2. Quali token sono disponibili nel tema ma non usati
3. Dove soli-boy usa valori hardcoded invece di token (debt design token)
4. Le override in `app-extra.css` (TSK-084 WCAG AA fix) e il loro razionale

## EP-019 ART-DIRECTOR STATEMENT

**INTENT:** Documentare lo stato attuale dell'uso del design system per guidare future decisioni
di refactoring verso token-first e per il futuro integrazione del pacchetto reale `@soli92/solids`.

**PROBLEM:** Senza un audit sistematico, il team non sa quanti token sono usati vs quanti sono
disponibili, né dove il codice bypassa i token con valori hardcoded. TSK-040 (integrazione DS reale)
è bloccato — quando sarà sbloccato, questo audit guiderà la migrazione.

**DESIGN RATIONALE:** L'audit è strutturato in 4 sezioni: (1) token usati, (2) token disponibili
non usati, (3) hardcoded values da sostituire, (4) override app-level con motivazione. Ogni sezione
ha implicazioni actionable per il futuro refactoring.

**CONSTRAINTS:**
- Solo documentazione, nessuna modifica al codice
- Non aprire nuovi gap per problemi trovati — solo documentare
- Basarsi sul codice esistente (nessuna installazione pacchetti nuovi)
