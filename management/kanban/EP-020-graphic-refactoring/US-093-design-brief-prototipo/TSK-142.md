# TSK-142 — UX/UI review del prototipo + gap analysis

## Context

Invocare `/ux-ui-review` sul prototipo generato in TSK-141. Questa review avviene **prima** dell'implementazione reale, per individuare problemi di UX prima che diventino costosi da correggere. I finding critici vengono embedded come note nei TSK di Phase 2.

## Invocazione

```
/ux-ui-review output/prototypes/ep020/
```

## Rubrica applicata

- Nielsen 10 (usabilità)
- 6 dimensioni UI visive (gerarchia, contrasto, spaziatura, tipografia, iconografia, motion)
- 5 dimensioni di flusso (entry, task, errore, feedback, exit)
- Pre-screen axe-playwright (se prototipo ha server dev attivo)

## Output atteso

`code_quality/reports/TSK-142-uxui-proto-review.md` — contenuto:
- Finding per tab (Play, Library, Settings, Info)
- Severity: critical / major / minor per ciascuno
- `rubric_ref` obbligatorio su ogni finding (`rubric_strict: true`)
- **Gap analysis**: mappa finding → TSK Phase 2 che deve risolverlo (es. `UX-EP020-01 → TSK-143`)
- Verdict complessivo del prototipo: pass / conditional / reject

Il gap analysis viene usato dall'orchestrator per arricchire i DoD dei TSK di Phase 2.

## Invariante

Questa review NON blocca l'implementazione se il verdict è `conditional`. Blocca solo se `reject` (R.D3: Critic non è oracolo — verdict non deterministico bloccante).
