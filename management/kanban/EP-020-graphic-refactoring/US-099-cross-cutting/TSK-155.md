# TSK-155 — TouchOverlay visual styling → Tailwind

## Context

TouchOverlay ha due livelli di CSS:
1. **Visual styling** (colori, bordi, radii, dimensioni relative) — migrabile a Tailwind
2. **Positioning mechanics** (absolute inset, safe-area `env()`, `touch-action`, landscape/portrait rules) — restano in `app-extra.css`, Tailwind non gestisce `env()` correttamente

## Migrazione (solo visual styling)

**D-pad buttons (`.dp`, `.dp-up/down/left/right/center`):**
```tsx
// Prima
className="dp dp-up"
// Dopo — solo visual properties in Tailwind:
className="dp dp-up bg-elevated border border-strong rounded-sm active:bg-hover select-none"
```
Le regole di posizionamento `.dp-up { top: 0; left: 44px; }` restano in `app-extra.css`.

**A/B buttons (`.ab`, `.ab-a/.ab-b/.ab-l/.ab-r/.ab-select/.ab-start`):**
```tsx
// .ab-a → bg color → Tailwind: bg-[var(--sd-color-pad-a)] text-[var(--sd-color-pad-a-bg)]
// .ab-b → bg color → Tailwind: bg-[var(--sd-color-pad-b)] text-[var(--sd-color-pad-b-bg)]
// L/R/Select/Start → bg-muted text-muted-foreground border border-border rounded
```

**Restano invarianti in `app-extra.css`:**
- `.sb-touch-overlay` — `position: absolute; inset: 0; pointer-events: none`
- `.sb-dpad`, `.sb-ab` — `position: relative; width: Xpx; height: Ypx`
- `.dp-up/down/left/right/center` — `position: absolute; top/left: ...`
- `@media (orientation: landscape)` player layout rules
- `env(safe-area-inset-*)` padding
- `touch-action: none`, `-webkit-user-select: none`
