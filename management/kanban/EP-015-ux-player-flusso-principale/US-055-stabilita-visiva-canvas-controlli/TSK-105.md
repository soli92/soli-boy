# TSK-105 — Aspect-ratio CSS invariante su .sb-screen (canvas idle no-jump)

## Context

**UX-021:** Il canvas in stato idle non ha aspect-ratio invariante in CSS: il container
`.sb-screen` collassa o cambia dimensione. Al primo Avvia, il canvas si "espande"
producendo un salto visivo percepibile.

`Player.tsx` (`[^src5: packages/app/src/components/Player/Player.tsx]`) genera uno stile
inline su `.sb-screen` tramite `videoSettingsToContainerStyle(effectiveSettings)` e usa
`data-video-scope` per il CSS scoped. TSK-086 ha già provato a chiudere questo: verificare
il report `code_quality/reports/TSK-086-*` prima di implementare.

Il fix atteso: `.sb-screen` deve avere `aspect-ratio` CSS impostato sempre, anche in
stato idle. Il valore deve provenire da una CSS custom property `--sb-canvas-aspect`
con default `10/9` (Game Boy) o `3/2` (default neutro). Il CSS scoped iniettato da
Player.tsx è il posto corretto (già usa `data-video-scope`).

## Acceptance Criteria

1. Il container `.sb-screen` ha `aspect-ratio` CSS impostato in ogni stato del Player
   (idle, running, paused). Il valore è derivato dall'`aspect` delle `videoSettings`
   correnti o da un default neutro configurabile.
2. In stato idle (nessuna ROM), il container occupa lo stesso spazio visivo dello stato
   running: nessun "salto" al primo Avvia verificabile visivamente.
3. Il fix non rompe l'esperienza fullscreen (TSK-035): in fullscreen il canvas
   continua a usare lo spazio massimo disponibile.
4. Test visivo (visual-oracle): screenshot stati idle vs running su mobile 375px —
   le dimensioni del `.sb-screen` sono equivalenti (tolleranza ±4px altezza).
5. Tutti i test esistenti passano senza modifiche.

## DoD

- [ ] `aspect-ratio` invariante aggiunto al CSS scoped di `.sb-screen` in Player.tsx
- [ ] Stato idle occupa stesso spazio di stato running
- [ ] Fullscreen non rotto (verifica con test existente TSK-035)
- [ ] Visual oracle screenshot idle vs running passanti
