# TSK-106 — Layout slot fissi controlli Player: posizione bottone primario stabile

## Context

**UX-020:** I bottoni dei controlli in `Player.tsx:456-494`
(`[^src5: packages/app/src/components/Player/Player.tsx]`) sono renderizzati in
posizioni diverse a seconda dello stato (idle: solo "Avvia"; running: "Pausa"+"Arresta";
paused: "Riprendi"+"Arresta"). Il bottone primario si sposta tra gli stati: l'utente
che lo cerca per memoria muscolare lo trova altrove.

Il fix richiede un layout a slot fissi: ogni slot ha un ruolo (primario, secondario,
fullscreen) e mostra un bottone diverso per stato, ma la posizione del primario è
sempre la stessa. I bottoni non applicabili allo stato corrente usano `visibility: hidden`
(preserva spazio) invece di `display: none` (rimuove spazio).

## Acceptance Criteria

1. Il container dei controlli in Player.tsx usa un layout a slot fissi (CSS Grid con 3
   colonne: primario | secondario | fullscreen) o flex con `min-width` deterministico.
2. Il bottone primario (Avvia/Pausa/Riprendi) è sempre nello stesso slot orizzontale
   in tutti e 3 gli stati.
3. I bottoni non applicabili allo stato corrente usano `visibility: hidden` (slot
   visibile ma bottone nascosto) OPPURE sono visibili con `disabled` + `aria-disabled="true"`.
   La scelta è documentata con un commento nel codice e coerente tra tutti gli stati.
4. Test visivo (visual-oracle): screenshot multi-stato (idle/running/paused) sui 2
   viewport (mobile/desktop) confermano che il bottone primario non si sposta
   visivamente.
5. Test funzionale (functional-oracle): sequenza Avvia → Pausa → Riprendi → Arresta
   verifica che il bottone primario è sempre nel stesso bounding box (tolleranza ±4px).
6. Test e2e esistenti sui bottoni Player passano senza modifiche.

## DoD

- [ ] Layout slot fissi implementato per i controlli Player
- [ ] `visibility: hidden` (o disabled) per bottoni non applicabili allo stato corrente
- [ ] Visual oracle screenshot multi-stato passanti
- [ ] Test e2e bottoni passanti
