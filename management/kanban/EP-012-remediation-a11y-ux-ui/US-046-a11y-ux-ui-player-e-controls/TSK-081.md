# TSK-081 — Scan a11y + UX/UI retroattivo: Player, controls, Settings, save-state, resa video (EP-003/004/005)

## Context

Remediation v2.18: il Player e i suoi componenti correlati (controlli, fullscreen, scala/aspect,
filtri, SaveStatePanel, export/import salvataggi in Settings, rimappatura comandi) sono in
produzione ma privi di `a11y_status`/`ux_ui_status`. Questo è il gruppo più ampio (10 TSK
sorgente) e copre l'area core dell'esperienza di gioco.
[^src: management/kanban/EP-012-remediation-a11y-ux-ui/US-046-a11y-ux-ui-player-e-controls/US-046.md §Acceptance Criteria]

**TSK sorgente coperti:**
- TSK-008 — Player: viewport + mount EmulatorJS (`Player.tsx`, viewport `.sb-screen`)
- TSK-022 — Player mount DOM + selezione engine (`Player.tsx`, container ref)
- TSK-014 — Player controls: pausa/ripresa/arresto (bottoni nel Player)
- TSK-017 — Settings: rimappatura comandi + profili (`Settings.tsx` sezione Controlli)
- TSK-032 — Player: pannello save state (`SaveStatePanel.tsx` — slot Salva/Carica/Elimina)
- TSK-041 — Bugfix canvas WasmBoy loadState (Player.tsx — `sb-canvas-host`)
- TSK-033 — Export/Import salvataggi (`Settings.tsx` sezione Dati — export/import file)
- TSK-035 — Schermo intero Fullscreen API (bottone toggle nel Player, `aria-pressed`)
- TSK-036 — Scala + aspect ratio persistiti (Settings sezione Resa video — due `<select>`)
- TSK-037 — Filtri base nearest/smoothing/scanline (Settings sezione Filtri)

**Ordering (verifiche retroattive — nessun nuovo develop):**
`visual-oracle (già eseguito) → /a11y → /ux-ui-review → valorizza frontmatter TSK sorgente`

## Technical Specs

### Scan a11y

Eseguire `/a11y TSK-081` coprendo i componenti Player + Settings nelle loro configurazioni chiave:

**Player (TSK-008/022/014/035/041):**
- Viewport `.sb-screen`: struttura semantica, `role`, focus quando il gioco è in esecuzione.
- Bottoni controlli (pausa/ripresa/arresto): `aria-label`, stato disabilitato, focus visible.
- Bottone Fullscreen: `aria-label` dinamico + `aria-pressed` (TSK-035 già implementati).
- `sb-canvas-host` (TSK-041): div con canvas — no interferenze struttura heading/landmarks.

**SaveStatePanel (TSK-032):**
- `role="region"` con `aria-label="Save state"`.
- Bottoni slot con `aria-label` espliciti ("Salva nello slot N", "Carica slot N", "Elimina slot N").
- Stato disabilitato: `disabled` HTML + `data-disabled` veicolati correttamente.
- Alert errori (`role="alert"` su engine-mismatch/not-found).

**Settings (TSK-017/033/036/037):**
- Sezione rimappatura comandi: keyboard bindings, focus management.
- Sezione Dati export/import: input file, `role="status"` su OK, `role="alert"` su KO.
- Sezione Resa video: due `<select>` con `<label>` associati.
- Sezione Filtri: opzioni filtro.

Applicare `run_a11y_scan` con:
- `standard: wcag22aa`
- `viewports: [mobile 375, desktop 1280]`
- `themes: [90s-party, dark]`
- `manual_checks N≥1` (regola di neutralità invariante — obbligatorio)

### Review UX/UI

Eseguire `/ux-ui-review TSK-081` applicando la rubrica completa:
- Nielsen: visibilità stato gioco (pausa/ripresa), controllo utente, prevenzione errori save/load, feedback export/import.
- Dimensioni UI: bottoni Player (target touch, contrasto), pannello save-state (leggibilità slot, meta timestamp), Settings (densità informativa).
- Dimensioni flusso: flusso avvia gioco → pausa → save-state → riprendi; flusso export → import salvataggi.

## Implementation Steps

1. Avviare `/a11y` sul Player in stati: `idle` (senza gioco), `running` (con gioco), `paused`, `fullscreen`.
2. Avviare `/a11y` su SaveStatePanel con slot popolati e vuoti.
3. Avviare `/a11y` su Settings (rimappatura / Dati / Resa video / Filtri).
4. Classificare tutti i finding: `critical` → fix FE o Q hard; `major` → conditional gestito.
5. Avviare `/ux-ui-review` su Player + Settings con rubrica completa.
6. Valorizzare `a11y_status` + `ux_ui_status` in ciascuno dei 10 TSK sorgente (+ `a11y_report` / `ux_ui_report`).
7. Aggiornare `updated:` su ciascun TSK sorgente modificato.
