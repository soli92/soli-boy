# TSK-084 — Fix token color-contrast 90s-party/dark + verifica cyberpunk (WCAG 2.2 AA)

## Context

Verifica retroattiva a11y EP-012 (TSK-079..083) ha prodotto 5 finding `color-contrast` di
severità **Major** (WCAG 2.2 AA, 1.4.3) con causa radice comune nei token del design system
`@soli92/solids@1.14.1` per i temi `90s-party` e `dark`. Gli stati coinvolti:

- `.sb-loader > label` (label dropzone FileLoader) — tema `dark` → finding in TSK-003
- `.sb-chip-on` (chip filtro attivo, Library) — tema `90s-party` → finding in TSK-038, TSK-040
- `.sb-danger.sb-btn` (pulsante "Arresta", Player controls) — tema `90s-party` → finding in TSK-014

I TSK sorgente affetti con `a11y_status: major` sono:
- **TSK-003** — FileLoader: picker + drag & drop (`packages/app/src/components/FileLoader/`)
- **TSK-014** — Player controls: pausa/ripresa/arresto (`packages/app/src/components/Player/`)
- **TSK-038** — Ricerca + filtro piattaforma (Library) (`packages/app/src/components/Library/`)
- **TSK-040** — Integrazione @soli92/solids reale (cross-cutting, token applicati globalmente)
- **TSK-044** — ThemeSelector + persistenza `data-theme` (`packages/app/src/components/ThemeSelector/`)

Report di dettaglio:
- `code_quality/reports/TSK-003-a11y-iter-1.{json,md}`

## Technical Specs

### Strategia di fix

**Percorso primario (preferito):** override delle CSS custom properties `sb-*` in
`packages/app/src/styles/` per i temi `90s-party` e `dark`, senza modificare il pacchetto
upstream `@soli92/solids`. Questo approccio:
- Non richiede publish/unpublish del DS.
- Mantiene la `solids-theme.css` esistente come punto di override app-level.
- È reversibile se `@soli92/solids` rilascia un fix upstream.

**Percorso alternativo:** patch diretta su `@soli92/solids` se il pacchetto è disponibile
in sviluppo locale con sorgenti accessibili (workspace monorepo Soli OS). In tal caso
documentare nel commit che la fix è upstream e richiedere publish.

### Token da correggere

Per ogni stato, determinare i valori correnti di foreground e background nei temi incriminati
(via DevTools o ispezione CSS), calcolare il nuovo valore conforme WCAG AA (≥4.5:1 testo
normale, ≥3:1 testo large/UI) usando un contrast checker (es. `@accessible-colors/core` o
APCA), e sovrascrivere le custom property nel blocco `[data-theme="90s-party"]` /
`[data-theme="dark"]` in `packages/app/src/styles/`:

1. **`.sb-loader > label`** — tema `dark`
   - Stato: label testuale del loader/dropzone FileLoader
   - WCAG richiesto: ≥4.5:1 (testo normale)
   - Azione: alzare il colore del testo label (`--sb-loader-label-color` o classe equivalente)
     o scurire il background del loader in `[data-theme="dark"]`.

2. **`.sb-chip-on`** — tema `90s-party`
   - Stato: chip filtro piattaforma in stato "attivo/selezionato" (Library, componente chip radiogroup)
   - WCAG richiesto: ≥4.5:1 (testo normale) o ≥3:1 se il testo è bold ≥18.66px
   - Azione: override foreground e/o background del chip attivo in `[data-theme="90s-party"]`.

3. **`.sb-danger.sb-btn`** — tema `90s-party`
   - Stato: pulsante "Arresta" (Player controls, variante pulsante di pericolo/danger)
   - WCAG richiesto: ≥4.5:1 (testo normale) o ≥3:1 se testo large/bold
   - Azione: override foreground (testo del pulsante) e/o background danger in
     `[data-theme="90s-party"]`.

### Task secondario — Scan tema cyberpunk (sub-gap iter-1)

Il tema `cyberpunk` non è stato scansionato nell'iter-1 dei TSK-079..083 (gap secondario
`ds-color-contrast-cross-cutting-90s-party-dark`). Dopo il fix dei 3 stati sopra, eseguire
uno scan a11y dedicato su:
- `.sb-loader > label` — tema `cyberpunk`
- `.sb-chip-on` — tema `cyberpunk`
- `.sb-danger.sb-btn` — tema `cyberpunk`

Classificare i finding e — se emergono `major`/`critical` — applicare lo stesso pattern di
override per `[data-theme="cyberpunk"]`. Documentare il risultato nel report di questo TSK.

## Implementation Steps

1. Leggere i report `code_quality/reports/TSK-{003,014,038,040,044}-a11y-iter-1.{json,md}`
   per estrarre i valori esatti di contrasto attuali e gli elementi DOM coinvolti.
2. Ispezionare le CSS custom properties dei temi `90s-party` e `dark` in
   `packages/app/src/styles/` (e in `node_modules/@soli92/solids/dist/css/` per
   comprendere i token sorgente).
3. Calcolare i valori corretti per i 3 stati (WCAG AA ≥4.5:1 o ≥3:1 secondo il tipo
   di testo) usando un contrast checker.
4. Applicare gli override in `packages/app/src/styles/` nei blocchi
   `[data-theme="90s-party"]` e `[data-theme="dark"]` appropriati.
5. Avviare `/a11y TSK-003` (tema dark) e `/a11y TSK-038` `/a11y TSK-040` `/a11y TSK-014`
   (tema 90s-party) + `/a11y TSK-044` (entrambi i temi) per verificare che 0 finding
   `color-contrast major/critical` residuino. Viewport: mobile 375px + desktop 1280px.
6. Aggiornare `a11y_status` e `a11y_report` nei frontmatter dei 5 TSK sorgente
   (TSK-003, TSK-014, TSK-038, TSK-040, TSK-044).
7. Eseguire scan tema `cyberpunk` sui 3 stati (`.sb-loader > label`, `.sb-chip-on`,
   `.sb-danger.sb-btn`). Documentare il risultato; se emergono finding, applicare override
   `[data-theme="cyberpunk"]` e ri-scansionare.
8. Aggiornare `wiki/gaps.md` (append-only): marcare `ds-color-contrast-cross-cutting-90s-party-dark`
   come risolto con data e riferimento a questo TSK.
