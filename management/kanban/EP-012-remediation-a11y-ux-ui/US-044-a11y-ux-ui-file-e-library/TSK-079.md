# TSK-079 — Scan a11y + UX/UI retroattivo: FileLoader, avviso legale, Library griglia (EP-001)

## Context

Remediation v2.18: i componenti FileLoader (picker+dnd), Dropzone a11y, avviso no-copyright e
Library griglia (EP-001) sono in produzione (`done`) ma privi di `a11y_status`/`ux_ui_status`
nei TSK sorgente. Questo task esegue la verifica retroattiva e valorizza i campi nei TSK sorgente.
[^src: management/kanban/EP-012-remediation-a11y-ux-ui/US-044-a11y-ux-ui-file-e-library/US-044.md §Acceptance Criteria]

**TSK sorgente coperti:**
- TSK-003 — FileLoader: selettore file + drag & drop (`packages/app/src/components/FileLoader/`)
- TSK-020 — Dropzone FileLoader attivabile da tastiera (a11y) (stessa cartella)
- TSK-006 — Avviso legale no-copyright (`packages/app/src/components/`)
- TSK-012 — Library: griglia delle ROM persistite (`packages/app/src/components/Library/`)

**Ordering (verifiche retroattive — nessun nuovo develop):**
`visual-oracle (già eseguito) → /a11y → /ux-ui-review → valorizza frontmatter TSK sorgente`

## Technical Specs

### Scan a11y

Eseguire `/a11y TSK-079` (o `/a11y packages/app/src/components/FileLoader`) per coprire:
- FileLoader: area drag & drop (`role="button"` + `tabIndex`), input file, messaggio errore.
- Avviso no-copyright: testo statico, contrasto, struttura heading.
- Library griglia: card ROM (`role`, focus), stato vuoto, griglia responsive.

Applicare `run_a11y_scan` con:
- `standard: wcag22aa`
- `viewports: [mobile 375, desktop 1280]`
- `themes: [90s-party, dark]`
- `include_interactive: false` (default factory)
- `manual_checks N≥1` (regola di neutralità invariante)

### Review UX/UI

Eseguire `/ux-ui-review TSK-079` sui componenti coperti applicando la rubrica:
- Nielsen: visibilità stato, controllo utente, prevenzione errori, help/documentazione.
- Dimensioni UI: contrasto, tipografia, spaziatura, touchability.
- Dimensioni flusso: percorso caricamento ROM → Library.

## Implementation Steps

1. Avviare `/a11y` sui componenti FileLoader + Library in viewport mobile+desktop e temi 90s-party+dark.
2. Classificare i finding: `critical`/`major` → aprire fix FE o segnalare all'owner; `minor`/`none` → annotare in report.
3. Avviare `/ux-ui-review` sugli stessi componenti con rubrica completa.
4. Per ogni TSK sorgente (TSK-003, TSK-020, TSK-006, TSK-012): valorizzare `a11y_status` + `a11y_report` + `ux_ui_status` + `ux_ui_report` nel frontmatter.
5. Aggiornare `updated:` su ciascun TSK sorgente modificato.

## Definition of Done

- [ ] `/a11y` eseguito su FileLoader, avviso no-copyright, Library griglia (mobile+desktop, 90s-party+dark)
- [ ] Finding classificati; `critical` → fix FE o Q hard aperta; `major` → conditional gestito o fix
- [ ] `/ux-ui-review` eseguito con rubrica anti-soggettività; finding documentati
- [ ] `manual_checks N≥1` inclusi nel report a11y (regola di neutralità)
- [ ] `a11y_status` valorizzato in TSK-003, TSK-020, TSK-006, TSK-012
