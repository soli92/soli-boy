# TSK-055 — Selezione runtime StorageAdapter: IndexedDB vs NativeFs

## Context

ADR-001 stabilisce che la stessa codebase è confezionata in più contenitori; ADR-002
prescrive che l'adapter `StoragePort` sia selezionato a runtime in base al contenitore.
Attualmente solo `IndexedDBAdapter` è in uso. Con TSK-054 disponibile, serve un punto
unico di selezione. [^src: design_&_architecture/decisions/ADR-002.md §Decisione]

## Technical Specs

- Creare (o aggiornare) `src/storage/select-adapter.ts`:
  - Se `window.electronAPI` è definito → istanzia `NativeFsAdapter`.
  - Altrimenti → istanzia `IndexedDBAdapter` (comportamento attuale su web e mobile).
- Il risultato è il singleton `StoragePort` iniettato nei servizi di dominio
  (`LibraryService`, `GameSession`, `SaveService`).
- Nessuna modifica al dominio: i servizi consumano solo l'interfaccia `StoragePort`.

## Implementation Steps

1. Creare `src/storage/select-adapter.ts` con la factory logic.
2. Aggiornare `src/main.tsx` (o `App.tsx`) per usare `selectAdapter()` anziché istanziare
   direttamente `IndexedDBAdapter`.
3. Typecheck: verificare che il tipo restituito sia `StoragePort` in entrambi i rami.
4. Test: mock `window.electronAPI` → verifica che restituisca `NativeFsAdapter`.

## DoD

- [ ] L'app web usa `IndexedDBAdapter` invariato.
- [ ] Con `window.electronAPI` mockato, l'app usa `NativeFsAdapter`.
- [ ] Nessuna modifica ai servizi di dominio.
- [ ] Build typecheck pulito.

## Dependencies

- TSK-054 (`NativeFsAdapter`).
