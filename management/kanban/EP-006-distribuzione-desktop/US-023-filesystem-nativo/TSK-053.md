# TSK-053 — Electron main process: finestra principale + bridge IPC filesystem

## Context

L'architettura (architecture-overview + wiki/entities/electron.md) prescrive due moduli Electron:
`electron/main.ts` (finestra principale + IPC del filesystem) e `electron/preload.ts`
(bridge sicuro verso il renderer). Questo task crea lo scheletro funzionante e il canale IPC
per le operazioni di lettura/scrittura file, su cui si appoggierà il `NativeFsAdapter`
(TSK-054). [^src: management/kanban/EP-006-distribuzione-desktop/US-023-filesystem-nativo/US-023.md §Business Rules]

> **ATTENZIONE — GAP APERTO:** il toolchain di packaging (Electron Forge vs electron-builder
> vs custom) NON è specificato in alcun ADR L4. Questo task è assegnato a `consumer: human`
> perché richiede la scelta del build tool da parte del lead-architect prima di poter
> finalizzare la configurazione. Vedi `wiki/gaps.md` (gap `electron-packaging-toolchain`).

## Technical Specs

- Stack: Electron (versione LTS corrente), TypeScript.
- Struttura:
  - `electron/main.ts` — crea `BrowserWindow`, carica `index.html` del renderer, registra
    canali IPC via `ipcMain.handle`.
  - `electron/preload.ts` — espone al renderer solo le API IPC in whitelist tramite
    `contextBridge.exposeInMainWorld`.
- Canali IPC minimi da registrare (per TSK-054):
  - `fs:readFile(path: string): Promise<Uint8Array>`
  - `fs:writeFile(path: string, data: Uint8Array): Promise<void>`
  - `fs:showOpenDialog(options): Promise<string[]>` (wrappa `dialog.showOpenDialog`)
  - `fs:showSaveDialog(options): Promise<string | undefined>` (wrappa `dialog.showSaveDialog`)
- `contextIsolation: true`, `nodeIntegration: false` (vincolo di sicurezza).
- Nessun dato lascia il dispositivo (ADR-002 invariante). [^src: design_&_architecture/decisions/ADR-002.md §Invariante]

## Implementation Steps

1. Scegliere il toolchain di packaging (decisione lead-architect — prerequisito gate).
2. Aggiungere dipendenza `electron` al `package.json` (devDependency).
3. Creare `electron/main.ts` con `BrowserWindow` + registrazione canali IPC.
4. Creare `electron/preload.ts` con `contextBridge`.
5. Aggiornare `tsconfig` per target Electron (dual target: browser renderer + Node main).
6. Verificare l'avvio dell'app desktop con `npm run electron:dev` (o equivalente).

## DoD

- [ ] `npm run electron:dev` apre la finestra desktop con il renderer.
- [ ] I canali IPC `fs:*` sono registrati e invocabili dal renderer.
- [ ] `contextIsolation: true`, `nodeIntegration: false`.
- [ ] Build typecheck pulito.

## Dependencies

- Decisione toolchain packaging (gate umano, lead-architect).
- TSK-054 (NativeFsAdapter) consuma i canali IPC definiti qui.
