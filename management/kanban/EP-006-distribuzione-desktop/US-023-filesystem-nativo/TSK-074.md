# TSK-074 — Estendi bridge IPC filesystem + delete reale in NativeFsAdapter

## Context

TSK-053 (done) ha esposto un bridge IPC minimale `window.soliboyDesktop` con sole primitive
`fs:readFile` / `fs:writeFile` / `fs:showOpenDialog` / `fs:showSaveDialog` (+ `update:event`).
Durante TSK-054 (done) il `NativeFsAdapter` ha dovuto aggirare l'assenza di
`unlink`/`mkdir`/`readdir`/`stat` con un **index-file scheme** e un **soft-delete via tombstone
zero-byte** per `removeRom` / `deleteSaveState`. È un workaround funzionante ma accumula file
fantasma su disco e impedisce un delete reale.
[^src: management/kanban/EP-006-distribuzione-desktop/US-023-filesystem-nativo/TSK-054.md §Implementation Steps]
[^src: packages/desktop/electron/preload.ts]

Questo task **non riapre TSK-053** (done, R.8): è un nuovo TSK che estende il bridge e fa
convergere il consumer (`NativeFsAdapter`) sul delete reale.

## Technical Specs

- Estendere `packages/desktop/electron/main.ts` con i canali IPC mancanti, registrati via
  `ipcMain.handle`, con i medesimi vincoli di sicurezza già in vigore (`contextIsolation: true`,
  `nodeIntegration: false`, nessun dato fuori dal dispositivo — ADR-002 §Invariante):
  - `fs:unlink(path: string): Promise<void>`
  - `fs:mkdir(path: string, opts?: { recursive?: boolean }): Promise<void>`
  - `fs:readdir(path: string): Promise<string[]>`
  - `fs:stat(path: string): Promise<{ exists: boolean; size: number; isDirectory: boolean }>`
- Esporre le stesse primitive in whitelist in `packages/desktop/electron/preload.ts`
  (`contextBridge` → `window.soliboyDesktop`), aggiornando `SoliboyDesktopApi`.
- Aggiornare l'interfaccia `NativeFsBridge` in
  `packages/app/src/storage/native-fs-adapter.ts` con i nuovi metodi.
- Sostituire il soft-delete tombstone con **`unlink` reale** in `removeRom` e `deleteSaveState`;
  usare `mkdir({recursive:true})` per garantire le directory di collezione invece di assumerle
  esistenti; usare `stat`/`readdir` dove semplifica l'index-file scheme (mantenendo però la
  compatibilità del formato chiavi/export con IndexedDBAdapter — invariante US-019).
- Path traversal guard nei nuovi handler main (confinare le operazioni alla base dir
  `~/.soli-boy/`), coerente con il principio di sicurezza del bridge esistente.

## Implementation Steps

1. `main.ts`: aggiungere gli `ipcMain.handle` per unlink/mkdir/readdir/stat con guard sul path.
2. `preload.ts`: aggiungere i metodi alla whitelist `api` + aggiornare `SoliboyDesktopApi`.
3. `native-fs-adapter.ts`: estendere `NativeFsBridge`; rimpiazzare tombstone → `unlink`;
   usare `mkdir`/`stat` dove elimina assunzioni.
4. Aggiornare gli unit test del NativeFsAdapter (mock bridge) per coprire il delete reale e
   l'assenza di tombstone residui; mantenere la guard zero-network.
5. Typecheck + test verdi; `npm run smoke` desktop se disponibile.

## DoD

- [ ] Bridge IPC espone unlink/mkdir/readdir/stat con `contextIsolation:true`/`nodeIntegration:false`.
- [ ] `removeRom`/`deleteSaveState` eseguono delete reale (nessun tombstone residuo) — test aggiornati.
- [ ] Compatibilità formato chiavi/export con IndexedDBAdapter preservata (US-019).
- [ ] Path traversal guard sui nuovi handler main.
- [ ] Nessuna chiamata di rete (invariante privacy ADR-002).
- [ ] Typecheck pulito + unit test storage verdi.

## Finding CQRL da assorbire (review TSK-054 iter-1)

Le seguenti finding del code-review di TSK-054 toccano `native-fs-adapter.ts` e vanno
risolte contestualmente (il file è già nel code_path). Riferimento:
`code_quality/reports/TSK-054-iter-1.json`.

- **F-1 (medium, design)**: discrepanza `exportSave`/`importSave` — presenti in
  `storage-port.md §Operazioni` (US-019) ma assenti da `port.ts`/adapter. Allineare la
  spec doc con nota esplicita "planned, US-019 out of sprint" (NON aggiungere i metodi
  all'adapter in questo TSK: sono operazioni di livello dominio US-019).
- **F-3 (low, robustness)**: `isNotFoundError` usa cast non strutturato; sostituire con
  type-guard `typeof err !== 'object' || err === null` prima del cast.
- **F-4 (medium, test)**: aggiungere test su `materializeRom` con blob 0-byte. Con il
  passaggio a `unlink` reale il tombstone sparisce: il test diventa anti-regressione che
  verifica l'assenza di entry residue nel manifest dopo `removeRom`/`deleteSaveState`.
- **F-5 (low, idiomaticity)**: chiarire il contratto path di `joinPath` su Windows;
  normalizzare `baseDir` nel costruttore o documentare che il main passa path POSIX.

**Fuori scope (tracciato a parte):** F-2 (`listRoms` eager blob I/O) richiede una decisione
sull'interfaccia `StoragePort` — non assorbito qui.
