# TSK-077 — Bridge IPC fs:getBaseDir + risoluzione baseDir assoluta

## Context

In TSK-055 la factory `selectAdapter()` costruisce `NativeFsAdapter` con un `baseDir`
**convenzionale** (`".soli-boy"`), perché il bridge desktop non espone al renderer il path
assoluto della base dir. Il main process (TSK-074) confina già le operazioni a
`path.resolve(os.homedir(), ".soli-boy")` con `guardPath`, ma il renderer non conosce questo
path: c'è un disallineamento potenziale tra ciò che l'adapter compone e ciò che il main
risolve/guarda. Serve esporre la base dir assoluta in modo autoritativo dal main.
[^src: management/kanban/EP-006-distribuzione-desktop/US-023-filesystem-nativo/TSK-055.md §Deviazioni e gap]

## Technical Specs

- `packages/desktop/electron/main.ts`: aggiungere `ipcMain.handle("fs:getBaseDir")` che ritorna
  il path assoluto già usato da `guardPath` (single source of truth — riutilizzare la stessa
  costante root, non ricalcolarla).
- `packages/desktop/electron/preload.ts`: esporre `getBaseDir(): Promise<string>` nella whitelist
  `api` + aggiornare `SoliboyDesktopApi`.
- `packages/app/src/storage/native-fs-adapter.ts`: estendere `NativeFsBridge` con `getBaseDir`;
  risolvere la base dir **lazy e memoizzata** alla prima operazione FS (così `selectAdapter()` e
  `App.tsx` restano sincroni — minimizza il blast radius). La `baseDir` convenzionale resta come
  fallback se il bridge non espone `getBaseDir` (retro-compatibilità / fail-soft esplicito).
- `packages/app/src/storage/select-adapter.ts`: nessun passaggio a `async` se si adotta la
  risoluzione lazy nell'adapter (verificare).

## Implementation Steps

1. main.ts: handler `fs:getBaseDir` che ritorna la root assoluta (riusa la costante di `guardPath`).
2. preload.ts: `getBaseDir` in whitelist + type.
3. native-fs-adapter.ts: `NativeFsBridge.getBaseDir?`; risoluzione lazy memoizzata del baseDir
   assoluto, con fallback al valore convenzionale se assente.
4. Test: mock bridge con `getBaseDir` → verifica che i path FS usino la root assoluta risolta;
   senza `getBaseDir` → fallback convenzionale. Mantieni guard zero-network.

## DoD

- [ ] `fs:getBaseDir` esposto dal bridge con `contextIsolation:true`/`nodeIntegration:false`.
- [ ] `NativeFsAdapter` usa la base dir assoluta autoritativa del main (lazy, memoizzata).
- [ ] `selectAdapter()`/`App.tsx` restano sincroni (nessun ripple async sui consumer).
- [ ] Fallback esplicito se `getBaseDir` assente (no path errati silenziosi).
- [ ] Typecheck pulito + test storage verdi.

## Dependencies

- TSK-074 (pattern di estensione bridge + `guardPath`).
- TSK-055 (factory che inietta il baseDir).
