# TSK-058 — e2e integrazione: carica ROM + salva su filesystem nativo (Electron)

## Context

Valida che in ambiente Electron il flusso end-to-end di caricamento ROM e salvataggio su
filesystem nativo funzioni correttamente, usando il `NativeFsAdapter` selezionato a runtime
(TSK-055). [^src: management/kanban/EP-006-distribuzione-desktop/US-023-filesystem-nativo/US-023.md §Acceptance Criteria]

> **DIPENDENZA SU GAP:** l'esecuzione in Electron richiede che la build desktop sia
> disponibile (TSK-053, TSK-056). In attesa della chiusura del gap packaging, il test
> può essere sviluppato con mock IPC (node environment + `window.electronAPI` stubbed)
> e promosso a Playwright+Electron non appena la build è disponibile.

## Technical Specs

- Framework: Playwright (già in CI) oppure test Vitest con IPC mockato.
- Fase 1 (agent): test con `window.electronAPI` mockato → verifica che `NativeFsAdapter`
  sia selezionato e le operazioni IPC siano invocate correttamente.
- Fase 2 (human, post-packaging): test E2E completo su Electron headless.
- ROM di test: `dmg-acid2.gb` (MIT, già in `public/test-roms/`).

## Implementation Steps

1. Creare `e2e/electron-storage.e2e.ts` con stub `window.electronAPI`.
2. Testare: selezione `NativeFsAdapter` → `addRom` chiama `fs:writeFile` → `listRoms`
   chiama `fs:readFile`.
3. Testare: salvataggio config chiama `fs:writeFile` con path `config.json`.
4. Annotare come `@slow @electron` per la fase E2E reale.
