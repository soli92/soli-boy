# TSK-057 — Auto-update Electron: rilevamento nuova versione e aggiornamento in-app

## Context

US-025 richiede che l'app desktop rilevi la disponibilità di nuove versioni e le applichi
senza reinstallazione manuale, comunicando all'utente l'esito. [^src: management/kanban/EP-006-distribuzione-desktop/US-025-aggiornamento-automatico/US-025.md §Acceptance Criteria]

> **ATTENZIONE — DUE GAP APERTI — GATE UMANO:**
> 1. `GAP-electron-packaging-toolchain` (toolchain build/packaging non deciso in L4).
> 2. `GAP-electron-autoupdate-mechanism` (meccanismo di auto-update non specificato in alcun
>    ADR o documento di architettura: `electron-updater` di electron-builder vs
>    `@electron/update-electron-app` vs Squirrel vs update server custom).
> Il lead-architect deve decidere entrambi i punti prima che questo task sia eseguibile.
> `consumer: human` — gate umano; non assegnabile ad agent finché i gap non sono chiusi.

## Technical Specs (provvisorie, da confermare dopo chiusura gap)

- Ipotesi di lavoro (da validare): `electron-updater` (electron-builder) oppure
  `@electron/update-electron-app` (GitHub Releases).
- Comportamento atteso:
  - Al lancio, il main process controlla se è disponibile una nuova versione.
  - Notifica l'utente tramite dialog o notifica di sistema.
  - L'utente può applicare l'aggiornamento; l'app si riavvia post-update.
  - In caso di errore, notifica l'esito negativo (no silent failure).
- Feed di aggiornamento: GitHub Releases (da confermare con owner).

## DoD

- [ ] L'app rileva la disponibilità di una nuova versione (meccanismo confermato).
- [ ] L'aggiornamento è applicabile senza reinstallazione manuale.
- [ ] L'esito (successo/errore) è comunicato all'utente.
- [ ] Funziona su Windows, macOS, Linux.

## Dependencies

- TSK-053 (Electron main process).
- TSK-056 (build packaging funzionante).
- Decisioni lead-architect su toolchain e meccanismo update.
