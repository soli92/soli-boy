# TSK-134 — MgbaRtcBridge: S-3511A BCD ↔ RtcState (GBA reale)

## Context

`MgbaEngine` espone attualmente `rtcBridge = null`
(stub `// ADR-009: bridge concreto pianificato Sprint 16`). Questo TSK implementa
`MgbaRtcBridge` — il bridge che traduce fra `RtcState` canonico e la sequenza
7-byte BCD del chip Seiko S-3511A usato dalle cartucce GBA RTC-dependent
(Pokémon Rubino/Zaffiro/Smeraldo, Boktai).
[^src: design_&_architecture/decisions/ADR-009.md §Decisione]

## Technical Specs

### Interfaccia da implementare (ADR-009 §4)

```ts
class MgbaRtcBridge implements RtcBridge {
  constructor(module: MgbaModule) {}
  hasRtc(): boolean;
  getRtcState(): RtcState | null;
  setRtcState(state: RtcState): void;
}
```

### hasRtc()

mGBA rileva automaticamente la presenza del chip S-3511A al `loadGame()`. Il modulo
mGBA non espone un'API pubblica `hasRtc()` diretta nell'attuale `mgba.d.ts`.

**Strategie di rilevamento (da validare — ricerca richiesta):**

**Opzione A — lettura header ROM**: i giochi GBA con S-3511A sono riconoscibili tramite
l'override database interno di mGBA (basato su Game Code / Title nel header ROM).
Leggere i byte `0xAC-0xB1` (Game Code, 4 byte) dalla ROM, consultare la lista nota
dei Game Code RTC-dependent. Vantaggio: nessuna dipendenza da API interna mGBA.
Svantaggio: lista statica da mantenere.

**Opzione B — probe memoria WASM**: mGBA espone `Module.FS` (Emscripten IDBFS).
Dopo `loadGame()`, tentare di accedere ai registri S-3511A via
`Module._rtcRead` / `Module._rtcWrite` (Emscripten-exported functions) se presenti.

**Opzione C — save state probe**: catturare uno snapshot, parsare il blob per verificare
la presenza del blocco RTC all'offset atteso nel formato save state di mGBA.

**Raccomandazione**: iniziare con Opzione A (Game Code lookup) per `hasRtc()`;
aggiungere commento con lista GBA RTC game codes nota + TODO per meccanismo automatico.

### getRtcState() e setRtcState()

Il chip S-3511A serializza in 7 byte BCD (ADR-009 §2):
`[year, month, day, dayOfWeek, hour, minute, second]`

**Meccanismo di accesso al runtime mGBA:**

Il save state di mGBA (`.ss0`) contiene lo snapshot completo dell'hardware GBA inclusi
i registri S-3511A. Strategia:

1. `saveState(MGBA_SNAPSHOT_SLOT)` → flush → `FS.readFile(saveStateFilePath(0))`.
2. Individuare l'offset del blocco RTC nel formato binario del save state mGBA.
   - Riferimento: sorgente mGBA (`src/gba/hardware.c`, struct `GBARTCSource`).
   - Il save state mGBA inizia con un magic header `"VBAm"` + versione, seguono
     blocchi tagged (format `GBASavedataChunk`). Il blocco RTC ha tag `"RTC "`.
3. `getRtcState()`: parse del blocco `"RTC "` → 7-byte BCD → `RtcState` UTC.
   - `dayOfWeek` è scartato (ADR-009 §2: derivato deterministicamente, non parte del modello canonico).
   - `year` 0–99 → 2000 + year.
4. `setRtcState(state)`: encoding inverso → patch blocco `"RTC "` nel save state blob →
   `FS.writeFile(path, patched)` → `loadState(slot)`.

**Encoding BCD `RtcState` → S-3511A (ADR-009 §2):**
```ts
function toBcd(n: number): number {
  return ((Math.floor(n / 10) & 0x0F) << 4) | (n % 10 & 0x0F);
}
const dayOfWeek = zellerCongruence(state.year, state.month, state.day); // 0–6
const bcd = [
  toBcd(state.year - 2000), // 00–99
  toBcd(state.month),       // 01–12
  toBcd(state.day),         // 01–31
  toBcd(dayOfWeek),         // 0–6
  toBcd(state.hour),        // 00–23
  toBcd(state.minute),      // 00–59
  toBcd(state.second),      // 00–59
];
```

## Implementation Steps

1. **Ricerca offset blocco RTC in save state mGBA**: carica ROM GBA con S-3511A (es.
   Pokémon Rubino), esegui `saveState(0)`, leggi i bytes, cerca magic `"RTC "` (4 byte
   ASCII). In alternativa consultare `src/gba/savedata.c` nel sorgente mGBA.
2. Creare `packages/app/src/core/mgba-rtc-bridge.ts` con la classe sopra.
3. Aggiungere unit test in `mgba-rtc-bridge.test.ts`:
   - `hasRtc()` su Game Code noto RTC (es. `"AXVE"` = Pokémon Ruby) → `true`.
   - `hasRtc()` su Game Code non-RTC (es. `"AXPE"` = Pokémon FireRed) → `false`.
   - Round-trip BCD: `setRtcState(state)` → `getRtcState()` ≡ `state`
     (mock `MgbaModule.saveState/loadState/FS`).
   - `zellerCongruence` restituisce il giorno corretto per date note.
4. Aggiornare `mgba-engine.ts`: rimuovere stub, inizializzare `MgbaRtcBridge` in `load()`.
5. `npm test` — 0 failure.
