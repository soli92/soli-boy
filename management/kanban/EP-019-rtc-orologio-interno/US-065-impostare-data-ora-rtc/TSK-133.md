# TSK-133 — WasmBoyRtcBridge: MBC3 registers ↔ RtcState (GBC reale)

## Context

TSK-125 ha introdotto `RtcBridge` come interfaccia di dominio. `WasmBoyEngine` espone
attualmente `rtcBridge = null` (stub `// ADR-009: bridge concreto pianificato Sprint 16`).
Finché il bridge rimane null, il flusso di impostazione data/ora (US-065) e la
persistenza fra sessioni (US-066) girano in modalità no-op: nessun dato viene letto o
scritto sull'engine Gambatte in esecuzione.

Questo TSK implementa `WasmBoyRtcBridge` — il bridge concreto che traduce fra il modello
canonico `RtcState` (ADR-009 §2) e i 5 registri MBC3 di Gambatte (RTC_S, RTC_M, RTC_H,
RTC_DL, RTC_DH). Alla fine del TSK `WasmBoyEngine.rtcBridge` punta a un'istanza reale e
i giochi GBC MBC3+RTC (Pokémon Oro/Argento/Cristallo) vedono date/ora coerenti.
[^src: design_&_architecture/decisions/ADR-009.md §Decisione]

## Technical Specs

### Interfaccia da implementare (ADR-009 §4)

```ts
class WasmBoyRtcBridge implements RtcBridge {
  constructor(wasmBoy: typeof WasmBoy, romHeaderByte0147: number) {}
  hasRtc(): boolean;           // true se romHeaderByte0147 ∈ {0x0F, 0x10}
  getRtcState(): RtcState | null;
  setRtcState(state: RtcState): void;
}
```

### hasRtc()

`WasmBoyEngine.load()` riceve i bytes della ROM: leggere il byte `0x0147` dal `Uint8Array`
prima di `WasmBoy.loadROM(bytes)` e passarlo al costruttore del bridge.
- `0x0F` = MBC3+TIMER+BATTERY → `hasRtc = true`
- `0x10` = MBC3+TIMER+RAM+BATTERY → `hasRtc = true`
- qualsiasi altro valore → `hasRtc = false`

### getRtcState() e setRtcState()

Il meccanismo si basa sul save state blob di WasmBoy. Gambatte serializza i registri
MBC3 nell'array `wasmboyMemory.wasmBoyInternalState` (Gambatte WASM internal state).

**Strategia di implementazione (da validare a runtime — ricerca richiesta):**

1. `await WasmBoy.saveState()` → blob con `wasmboyMemory`.
2. Individuare gli offset dei registri MBC3 dentro `wasmBoyInternalState`.
   - Riferimento: sorgente Gambatte (`src/memory/cartridge/mbc/mbc3.cpp`,
     `rtcRegs[]` e `latchedRtcRegs[]`). Lo stato serializzato è il
     `wasmBoyInternalState` Uint8Array; gli offset dipendono dall'ABI WASM di
     Gambatte compilato in WasmBoy.
   - Approccio empirico: caricare una ROM MBC3 con data nota, salvare più save state
     con date diverse, diff dei blob per isolare i byte variabili.
3. `getRtcState()`: legge `wasmBoyInternalState[offset_S..offset_DH]` → decoding
   MBC3 → `RtcState`. Conversione inversa da wall-clock UTC via `latchedTime`:
   `epoch = latchedTime + (DH_day_low | (DH & 0x01) << 8) * 86400 + H * 3600 + M * 60 + S`
   → decomposizione UTC in `year/month/day/hour/minute/second`.
4. `setRtcState(state)`: encoding `RtcState` → epoch seconds UTC →
   `latchedTime = epoch` → registri MBC3 (`RTC_S = epoch % 60`, ecc.) → patch
   `wasmBoyInternalState` → `await WasmBoy.loadState(patched)` → `resumeIfPlaying()`.

### Wiring in WasmBoyEngine

Dopo `WasmBoy.loadROM(bytes)` (e dunque a `load()` concluso):

```ts
// rimuovere il commento ADR-009 stub e sostituire con:
this.rtcBridge = new WasmBoyRtcBridge(WasmBoy, bytes[0x0147]);
```

Il campo `rtcBridge` diventa `readonly` solo dopo l'inizializzazione: cambiare il tipo
da `readonly` a un campo privato con getter pubblico, oppure assegnarlo nel costruttore
(dipende dall'approccio scelto con l'API WasmBoy).

## Implementation Steps

1. **Ricerca offset MBC3**: caricare ROM MBC3+RTC (Pokémon Gold), eseguire
   `WasmBoy.saveState()`, stampare `wasmboyMemory.wasmBoyInternalState` in hex.
   Variare la data nel gioco e confrontare. Oppure consultare sorgente Gambatte
   (`deps/gambatte-core/src/memory/cartridge/mbc/mbc3.cpp`).
2. Creare `packages/app/src/core/wasmboy-rtc-bridge.ts` con la classe sopra.
3. Aggiungere unit test in `wasmboy-rtc-bridge.test.ts`:
   - `hasRtc(0x0F)` → `true`; `hasRtc(0x10)` → `true`; `hasRtc(0x13)` → `false`.
   - Round-trip encode/decode MBC3: `setRtcState(state)` → `getRtcState()` ≡ `state`
     (mock `WasmBoy.saveState/loadState`).
4. Aggiornare `wasmboy-engine.ts`: rimuovere stub `rtcBridge = null`,
   inizializzare `WasmBoyRtcBridge` in `load()`.
5. Aggiornare `hasRtc(platform)` in `rtc-service.ts`: il fallback conservativo
   `'gbc' → true` può restare come safety net ma la detection runtime via
   `WasmBoyRtcBridge.hasRtc()` è ora la sorgente di verità.
6. `npm test` da `packages/app` — 0 failure.

## Note

L'offset esatto dei registri MBC3 in `wasmBoyInternalState` è il punto critico non
documentato. Il dev agent deve condurre la ricerca empirica o consultare il sorgente
Gambatte come primo step. Se l'offset non è stabile fra versioni di WasmBoy, aggiungere
un test di "sanity check offset" che fallisce in modo leggibile all'aggiornamento della
lib (pattern di difesa preventiva).
