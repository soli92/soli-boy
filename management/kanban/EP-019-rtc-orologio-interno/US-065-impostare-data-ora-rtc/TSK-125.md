# TSK-125 — RtcService: interfaccia dominio RTC (getRtcState / setRtcState / hasRtc)

## Context

Introdurre il servizio di dominio `RtcService` che astrae il concetto di orologio interno
dell'emulatore. Il servizio espone tre operazioni: (1) `hasRtc(platform)` — determina se
la piattaforma emulata corrente ha un orologio interno; (2) `getRtcState(engine)` — legge
lo stato corrente dell'orologio dal core in esecuzione; (3) `setRtcState(engine, rtcState)`
— applica al core uno stato data/ora impostato dall'utente.

L'implementazione è **tecnologia-agnostica a livello di tipo** (`RtcState` come
oggetto wall-clock con campi `year`, `month`, `day`, `hour`, `minute`, `second`, semantica
UTC), conforme ad ADR-009 §2. I metodi di bridge verso il core engine (`getRtcState` /
`setRtcState`) espongono hook che le concrete implementazioni engine (WasmBoyEngine,
MgbaEngine) dovranno riempire — i bridge concreti (`WasmBoyRtcBridge`, `MgbaRtcBridge`)
sono TSK Sprint 16 fuori scope EP-019.

Il servizio integra `hasRtc` con la mappa piattaforme esistente
(`core-wrapper.md §Mapping piattaforma → core`). Conforme ad ADR-009 §1, la detection
canonica è per-cartuccia (delegata al bridge runtime); per il TSK-125 (dominio + test)
il campo `hasRtc(platform)` resta un **fallback conservativo** (`true` per GB/GBC,
`false` per GBA/arcade) documentato con `// ADR-009: fallback conservativo — detection
runtime canonica via RtcBridge.hasRtc() implementata nei bridge concreti Sprint 16`.

## Technical Specs

- **Nuovo file:** `packages/app/src/domain/rtc-service.ts`
  - Tipo `RtcState = { year: number; month: number; day: number; hour: number; minute: number; second: number }`
  - Tipo `RtcCapability = { hasRtc: boolean }`
  - Funzione `hasRtc(platform: string): boolean` — ritorna `true` per `'gb'` e `'gbc'` (conservative fallback ADR-pending), `false` altrimenti.
  - Interfaccia `RtcBridge` con `getRtcState(): RtcState | null` e `setRtcState(state: RtcState): void` — da implementare negli adapter engine.
  - Classe/funzione `RtcService` con:
    - `getRtcState(bridge: RtcBridge): RtcState | null`
    - `setRtcState(bridge: RtcBridge, state: RtcState): void`
    - `validateRtcState(state: RtcState): boolean` — range check (anno ≥ 2000, mese 1-12, giorno 1-31, ora 0-23, minuto 0-59, secondo 0-59).
- **Test:** `packages/app/src/domain/rtc-service.test.ts`
  - `hasRtc('gb')` → `true`; `hasRtc('gba')` → `false`; `hasRtc('arcade')` → `false`.
  - `validateRtcState` rifiuta mese=13, giorno=32, ora=24.
  - `validateRtcState` accetta stato valido (es. 2026-06-30 12:00:00).
  - `setRtcState` chiama `bridge.setRtcState` con lo stato passato.
  - `getRtcState` ritorna il valore del bridge.
