# TSK-135 — e2e bridge reale: sblocca test.describe.skip ep019-rtc (GBC + GBA)

## Context

`ep019-rtc.e2e.ts` contiene un `test.describe.skip` marcato
`"bridge concreto Sprint 16 — ADR-009 §4 follow-up"` con due test scheletrici:
1. Bridge Gambatte/MBC3 legge/scrive RTC (ROM GBC MBC3+RTC)
2. Bridge mGBA legge/scrive RTC (ROM GBA S-3511A)

Con TSK-133 e TSK-134 completati, il blocco `test.describe.skip` può essere rimosso
e sostituito con test funzionali reali.

## Technical Specs

### Nota su ROM fixtures

I test completi end-to-end (carica ROM → avvia gioco → interagisce con RTC nel gioco)
richiedono ROM con MBC3+RTC (Pokémon Oro/Argento/Cristallo) e ROM con S-3511A
(Pokémon Rubino/Zaffiro/Smeraldo). Queste ROM sono coperte da copyright — **gate umano**
per aggiunta a `public/test-roms/`.

**Cosa è testabile senza ROM proprietarie:**

A. **hasRtc() detection**: creare un ROM blob sintetico minimale con soli i
   16 byte necessari (header `0x00..0x4F` + dummy + `0x0147 = 0x0F`). Caricarlo
   nell'app e verificare che `RtcSection` diventi visibile nel Settings.

B. **Sezione RTC visibile/nascosta**: il flusso UI (visibilità condizionale di
   `RtcSection`) si basa su `hasRtc()` e può essere validato con ROM sintetica
   (nessun gioco reale in esecuzione necessario).

C. **Round-trip via StubEngine**: i test e2e già esistenti in `ep019-rtc.e2e.ts`
   (Scenari 1–11, non skippati) usano `StubRtcBridge` e coprono il flusso UI
   completo — questi sono già verdi.

**Cosa rimane come human gate:**
- e2e con avvio ROM MBC3+RTC reale + verifica che `getRtcState()` ritorni non-null.
- e2e con Pokémon Oro: impostare data → riavviare → verificare ora del gioco riflessa.

### Test da implementare (sostituiscono il blocco skip)

```
describe("EP-019 RTC — bridge concreto Sprint 16")
  test "WasmBoyRtcBridge: hasRtc() true su ROM header MBC3+RTC (0x0F)"
    → crea ROM sintetica con byte 0x0147 = 0x0F
    → carica nell'app via file input
    → Settings aperto durante gioco → RtcSection visibile
  test "WasmBoyRtcBridge: hasRtc() false su ROM header senza RTC (0x13 = MBC3+RAM)"
    → crea ROM sintetica con byte 0x0147 = 0x13
    → RtcSection NON visibile
  test "MgbaRtcBridge: hasRtc() true su ROM GBA con Game Code S-3511A noto"
    → crea ROM sintetica GBA con Game Code "AXVE" (Pokémon Ruby)
    → RtcSection visibile
  test "MgbaRtcBridge: hasRtc() false su ROM GBA senza RTC"
    → usa gba-tests-thumb.gba esistente (non RTC)
    → RtcSection NON visibile
```

**Nota**: i test usano app in stub mode (URL param `?rtcPlatform=gbc|gba&rtcBridge=stub`)
per il flusso UI, e ROM sintetiche per la detection. Vedere wiring in `App.tsx:318` e
`App.tsx:757` (stub mode già implementato da TSK-132).

### Aggiornamento test.describe.skip → test.describe

Rimuovere il `test.describe.skip` e rimpiazzare con `test.describe` + i test sopra.
Aggiungere `test.fixme` per i due test originali che richiedono ROM proprietarie, con
messaggio canonico: `"richiede ROM con copyright — human gate: aggiungere fixture a
public/test-roms/ per sbloccare"`.

## Implementation Steps

1. Leggere `ep019-rtc.e2e.ts` per capire il pattern helper esistente
   (helper `createSyntheticGbRom` o simili potrebbero già esistere).
2. Creare helper `createSyntheticRomWithHeader(headerByte0147: number): Uint8Array`
   (16 byte di padding + 0x0147 impostato).
3. Creare helper `createSyntheticGbaRomWithGameCode(code: string): Uint8Array`
   (ROM GBA minima con Game Code all'offset `0xAC`).
4. Implementare i 4 test descritti sopra nel nuovo `test.describe`.
5. Convertire i 2 test originali in `test.fixme` con messaggio.
6. Eseguire e2e: `npx playwright test ep019-rtc.e2e.ts` — 0 failure.
