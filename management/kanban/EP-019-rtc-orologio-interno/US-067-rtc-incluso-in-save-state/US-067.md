# US-067 — Stato dell'orologio interno incluso nei save state

## Descrizione

Come giocatore, voglio che lo stato dell'orologio interno dell'emulatore faccia parte dell'istantanea creata dal save state, affinché ripristinare un save state mi riporti esattamente allo stato temporale del momento in cui l'avevo creato, senza incoerenze fra istantanea del gioco e orologio.

## Business Rules

- Lo stato dell'orologio interno del gioco in esecuzione, quando la piattaforma emulata ne prevede uno, è parte integrante dell'istantanea creata da un save state. [^src: wiki/concepts/save-state-e-sram.md §Contesto]
- Al ripristino di un save state, oltre allo stato dell'emulatore (US-016), viene ripristinato anche lo stato dell'orologio interno presente nell'istantanea: il gioco vede esattamente la data e l'ora che erano impostate al momento della creazione del save state.
- Più save state distinti dello stesso gioco possono contenere stati dell'orologio interno differenti, senza interferire fra loro.
- Per giochi appartenenti a piattaforme senza orologio interno, il comportamento dei save state esistenti (US-016) resta invariato: nessun campo aggiuntivo è richiesto né viene introdotto.
- I save state creati prima dell'introduzione di questa storia restano caricabili: in mancanza dello stato dell'orologio interno nell'istantanea, il ripristino procede senza modifiche all'orologio interno corrente del gioco (compatibilità all'indietro).
- Lo stato dell'orologio interno incluso nel save state è dato locale come tutto il save state: nessun invio a server esterni (RNF-06). [^src: wiki/syntheses/requisiti-funzionali-soli-boy.md §Requisiti non funzionali (RNF-01..RNF-08)]
- L'inclusione dello stato dell'orologio interno nei save state vale anche per il flusso export/import dei salvataggi (US-019): esportare e re-importare un save state preserva lo stato dell'orologio interno contenuto.

## Acceptance Criteria

- [ ] Avviando un titolo di una piattaforma con orologio interno, impostando data/ora dal Settings (US-065) a un valore noto, creando un save state e successivamente modificando data/ora a un valore diverso: ripristinando il save state, il gioco torna a vedere il valore noto del momento della creazione.
- [ ] Creando due save state distinti dello stesso gioco con valori dell'orologio interno differenti, ciascuno preserva il proprio valore in modo indipendente; ripristinando uno o l'altro si ottiene il rispettivo valore.
- [ ] Per un gioco di una piattaforma senza orologio interno, il comportamento di creazione e ripristino dei save state resta identico a quello attuale (nessun campo nuovo, nessuna asserzione nuova): US-016 continua a essere verificata senza regressioni.
- [ ] Caricando un save state creato prima dell'introduzione di questa storia (privo dello stato dell'orologio interno), il ripristino procede e l'orologio interno corrente del gioco non viene modificato (compatibilità all'indietro).
- [ ] Esportando un save state che contiene lo stato dell'orologio interno e re-importandolo (US-019), il save state importato, al ripristino, riporta il gioco alla stessa data/ora del save state originale.
- [ ] Nessuna chiamata di rete è effettuata a seguito di creazione o ripristino di save state contenenti lo stato dell'orologio interno.
