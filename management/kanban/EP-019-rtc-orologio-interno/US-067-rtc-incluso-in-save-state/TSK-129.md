# TSK-129 — SaveService: includi snapshot RTC in putSaveState / ripristina in restoreSaveState (compat all'indietro)

## Context

Estendere il flusso save-state per includere lo stato dell'orologio interno nell'istantanea
persistita. Il salvataggio (`putSaveState`) deve catturare e serializzare il `RtcState`
corrente accanto al blob di stato emulatore; il ripristino (`restoreSaveState`) deve
estrarre e applicare il `RtcState` dall'istantanea, con compatibilità all'indietro: save
state privi del campo RTC vengono caricati normalmente senza modifiche all'orologio corrente.
[^src: management/kanban/EP-019-rtc-orologio-interno/US-067-rtc-incluso-in-save-state/US-067.md §Business Rules]
[^src: design_&_architecture/api_specs/storage-port.md §Operazioni]
[^src: design_&_architecture/db_schemas/indexeddb-stores.md §Object stores]
[^src: design_&_architecture/decisions/ADR-009.md §Decisione]

## Technical Specs

- **Schema `saveStates` — campo aggiuntivo opzionale** (conforme ADR-009 §3):
  - Aggiungere campo `rtcState?: RtcState` alla struttura della entry `saveStates` in IDB.
  - Il campo è opzionale: entry preesistenti prive del campo restano valide (compat all'indietro by-design).
  - Nessun bump di versione IDB richiesto (campo aggiuntivo su store esistente, IDB è schema-less per i campi non-keyPath/index).

- **`SaveService.putSaveState(romId, slot, snapshotBlob, rtcBridge?)`:**
  - Nuovo parametro opzionale `rtcBridge?: RtcBridge | null`.
  - Se `rtcBridge` non null e `getRtcState(rtcBridge)` non null: aggiungere `rtcState` alla entry `saveStates` persistita.
  - Se `rtcBridge` null o `getRtcState` ritorna null: `rtcState` assente dalla entry (comportamento invariato).

- **`SaveService.restoreSaveState(saveStateId, rtcBridge?)`:**
  - Nuovo parametro opzionale `rtcBridge?: RtcBridge | null`.
  - Dopo aver ripristinato il blob di stato emulatore:
    - Se la entry contiene `rtcState` e `rtcBridge` non null: chiamare `setRtcState(rtcBridge, entry.rtcState)`.
    - Se la entry non contiene `rtcState` (save state pregresso): nessuna modifica all'orologio corrente (compat all'indietro).
  - Un fallimento del ripristino RTC non interrompe il ripristino dello stato emulatore (best-effort, `console.warn`).

- **Export/import (US-019 — già implementato in TSK-033):**
  - Il blob serializzato da export include già tutto il record IDB: il campo `rtcState` viene esportato/importato automaticamente senza modifiche aggiuntive al flusso export/import esistente.

- **Test:** `packages/app/src/domain/save-service.test.ts`
  - `putSaveState` con bridge mock non null → entry IDB contiene `rtcState`.
  - `putSaveState` con bridge null → entry IDB non contiene `rtcState`.
  - `restoreSaveState` su entry con `rtcState` + bridge mock → `setRtcState` chiamato.
  - `restoreSaveState` su entry senza `rtcState` (save pregresso) → `setRtcState` non chiamato, restore completa normalmente.
  - `restoreSaveState` con `setRtcState` che rigetta → restore procede, `console.warn` emesso.

## Implementation Steps

1. Aggiornare la firma di `putSaveState` e `restoreSaveState` in `SaveService` con il parametro `rtcBridge?`.
2. Aggiungere la logica di capture RTC in `putSaveState` e di restore RTC in `restoreSaveState`.
3. Aggiornare i test `save-service.test.ts` con i casi specificati.
4. Eseguire `npm test` e verificare 0 failure, nessuna regressione sui test save-state esistenti (TSK-030/031/032/034).

## Definition of Done

- [ ] `putSaveState` include `rtcState` nella entry se bridge disponibile.
- [ ] `restoreSaveState` applica `rtcState` se presente nella entry; no-op se assente (compat all'indietro).
- [ ] Save state pregressi (senza `rtcState`) caricano senza errori.
- [ ] Test `save-service.test.ts` passano (0 failure, no regressioni).
- [ ] Code review approvata.
