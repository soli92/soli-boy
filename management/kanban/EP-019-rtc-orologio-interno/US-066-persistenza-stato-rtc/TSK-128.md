# TSK-128 — GameSession: wiring RtcService ↔ engine ↔ StoragePort (persist on stop / restore on start)

## Context

Integrare il ciclo di vita dell'RTC in `GameSession`: al termine della sessione di gioco
(`stop`) persistere lo stato corrente dell'orologio interno via `StoragePort.putRtcState`;
all'avvio di una sessione (`load/start`) ripristinare lo stato RTC precedentemente
persistito per quel gioco via `StoragePort.getRtcState` e applicarlo all'engine via
`RtcService.setRtcState`. Questo garantisce la continuità dell'orologio interno fra
sessioni distinte, come richiesto da US-066.
[^src: management/kanban/EP-019-rtc-orologio-interno/US-066-persistenza-stato-rtc/US-066.md §Business Rules]
[^src: design_&_architecture/architecture-overview.md §Servizi di dominio]
[^src: design_&_architecture/decisions/ADR-009.md §Decisione]

## Technical Specs

- **`GameSession.stop()`:**
  - Se `hasRtc(platform)` e l'engine espone `RtcBridge`: chiamare `getRtcState(bridge)` e, se non null, chiamare `storagePort.putRtcState(romId, state)` best-effort (try/catch: un fallimento non interrompe lo stop).
  - Log `console.warn` in caso di fallimento della persistenza RTC.

- **`GameSession.load()` / inizio partita:**
  - Se `hasRtc(platform)`: chiamare `storagePort.getRtcState(romId)`.
  - Se trovato: chiamare `RtcService.setRtcState(bridge, persistedState)` best-effort.
  - Se non trovato (prima sessione): non applicare nulla (il core usa il suo default).
  - Un fallimento del ripristino non blocca l'avvio del gioco (best-effort, log `console.warn`).

- **Interfaccia engine:** `EmulatorEngine` estesa con campo opzionale `rtcBridge?: RtcBridge | null` (conforme ADR-009 §4).
  - `WasmBoyEngine` e `MgbaEngine`: aggiungere stub `rtcBridge = null` marcato `// ADR-009: bridge concreto (WasmBoyRtcBridge / MgbaRtcBridge) pianificato Sprint 16 — stub null mantiene flusso best-effort no-op`.
  - `StubEngine`: aggiungere `rtcBridge = null` (test deterministici invarianti; override-abile via `StubRtcBridge` in test).

- **Test:** `packages/app/src/domain/game-session.test.ts`
  - Stop con piattaforma RTC + bridge mock → `putRtcState` chiamato con stato corretto.
  - Stop con piattaforma senza RTC → `putRtcState` non chiamato.
  - Load con stato persistito + piattaforma RTC → `setRtcState` chiamato.
  - Load senza stato persistito → `setRtcState` non chiamato, gioco avviato normalmente.
  - `putRtcState` che rigetta → stop procede, `console.warn` emesso, no throw a monte.

## Implementation Steps

1. Estendere interfaccia `EmulatorEngine` con `rtcBridge?: RtcBridge | null`.
2. Aggiungere stub `rtcBridge = null` a WasmBoyEngine, MgbaEngine, StubEngine.
3. Aggiungere logica persist-on-stop e restore-on-start in `GameSession`.
4. Aggiornare `game-session.test.ts` con i casi specificati.
5. Eseguire `npm test` e verificare 0 failure.
