# TSK-127 — Storage: nuovo store `rtcState` + operazioni StoragePort (putRtcState / getRtcState / deleteRtcState)

## Context

Estendere lo schema IndexedDB con un quinto object store `rtcState` dedicato alla
persistenza dello stato dell'orologio interno, distinto dalla SRAM (`sram`) e dai save
state (`saveStates`) come richiesto da US-066. Aggiungere alla porta di persistenza
(`StoragePort`) le tre operazioni necessarie: `putRtcState`, `getRtcState`, `deleteRtcState`.
[^src: management/kanban/EP-019-rtc-orologio-interno/US-066-persistenza-stato-rtc/US-066.md §Business Rules]
[^src: design_&_architecture/db_schemas/indexeddb-stores.md §Object stores]
[^src: design_&_architecture/api_specs/storage-port.md §Operazioni]
[^src: design_&_architecture/decisions/ADR-009.md §Decisione]

## Technical Specs

- **Schema IndexedDB — nuovo store `rtcState`** (conforme ADR-009 §3):
  - `keyPath`: `romId` (FK logica → `roms.id`, invariante di dominio)
  - Campi: `romId: string`, `state: RtcState`, `updatedAt: string` (ISO 8601 UTC), `schemaVersion: number` (= 1, riservato per future migration)
  - Nessun index aggiuntivo richiesto (accesso sempre per `romId`).
  - Versione database: bump da versione attuale a versione+1 (migration `onupgradeneeded`).
  - `updatedAt` e `schemaVersion` sono gestiti internamente dall'adapter (`new Date().toISOString()`, costante `1`) e NON esposti al dominio.

- **`StoragePort` — nuove operazioni:**
  - `putRtcState(romId: string, state: RtcState): Promise<void>`
  - `getRtcState(romId: string): Promise<RtcState | null>` (null se non trovato)
  - `deleteRtcState(romId: string): Promise<void>` (idempotente — no-op se assente)

- **`IndexedDBAdapter` — implementazione:**
  - `putRtcState`: `put` sull'object store `rtcState`.
  - `getRtcState`: `get` su `rtcState`, ritorna `null` se `undefined`.
  - `deleteRtcState`: `delete` su `rtcState`.
  - `NativeFsAdapter` (desktop): aggiungere stub `putRtcState`/`getRtcState`/`deleteRtcState` che scrivono/leggono un file `<romId>.rtc.json` nella directory dei dati di gioco (analogo pattern SRAM, conforme ADR-009 §3). Marcato `// planned: piena implementazione NativeFs in TSK desktop dedicato`.

- **`removeRom` — cascade delete:** estendere la logica di rimozione ROM per chiamare `deleteRtcState(romId)` assieme agli altri dati del gioco (SRAM, save state), garantendo che la rimozione dalla libreria elimini anche lo stato RTC associato.

- **Test:** `packages/app/src/storage/storage-port.test.ts`
  - `putRtcState` poi `getRtcState` → ritorna lo stesso oggetto.
  - `getRtcState` su `romId` inesistente → `null`.
  - `deleteRtcState` poi `getRtcState` → `null`.
  - `deleteRtcState` su `romId` inesistente → no-op (no throw).

## Implementation Steps

1. Aggiornare `indexeddb-adapter.ts`: bump versione DB, aggiungere `createObjectStore('rtcState', { keyPath: 'romId' })` in `onupgradeneeded`.
2. Aggiungere i metodi `putRtcState`, `getRtcState`, `deleteRtcState` all'interfaccia `StoragePort` e all'implementazione `IndexedDBAdapter`.
3. Aggiungere cascade delete in `removeRom`.
4. Aggiungere stub `NativeFsAdapter` marcato ADR-pending.
5. Aggiornare `storage-port.test.ts` con i casi specificati.
6. Eseguire `npm test` e verificare 0 failure.
