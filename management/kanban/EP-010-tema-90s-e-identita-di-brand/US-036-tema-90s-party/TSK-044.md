# TSK-044 — ThemeSelector + persistenza `data-theme` (US-036)

## Context

L'app usa già `@soli92/solids` (installato in v1.14.1, DS reale — gap
`design-system-real-package` CHIUSO via TSK-040). L'`index.html` imposta
`data-theme="dark"` hard-coded sull'elemento `<html>`. US-036 richiede:
(1) il tema `90s-party` sia applicabile via `data-theme`; (2) l'utente possa
scegliere il tema da Settings; (3) la scelta sia persistita tra sessioni. [^src: management/kanban/EP-010-tema-90s-e-identita-di-brand/US-036-tema-90s-party/US-036.md §Business Rules]

## Technical Specs

### 1. ThemePort (storage/port.ts o file dedicato)

Definire un'interfaccia `ThemePort` analoga a `VideoSettingsPort`:

```ts
export interface ThemePort {
  load(): Promise<string | null>;
  save(theme: string): Promise<void>;
}
```

Implementazione concreta via `ConfigPort` (chiave canonica `"ui-theme"`,
store `config` IndexedDB già esistente). Stessa factory pattern di
`makeVideoSettingsPort` → `makeThemePort(config: ConfigPort): ThemePort`.

### 2. useTheme hook

Hook React `useTheme(port?: ThemePort)`:
- Al mount: legge la preferenza da `port?.load()`. Default: `"90s-party"` (nuova
  identità di brand; `dark` rimane disponibile come alternativa).
- Applica il tema impostando `document.documentElement.setAttribute("data-theme", theme)`.
- Espone `{ theme, setTheme }`. `setTheme` aggiorna l'attributo E persiste via porta.

**Assunzione annotata:** il default al primo avvio è `"90s-party"` (in linea con
il posizionamento brand ratificato). Se l'owner preferisce mantenere `"dark"`
come default iniziale (breaking change soft), annotare la decisione nel TSK
ma non variare la struttura.

### 3. ThemeSelector component

`packages/app/src/components/ThemeSelector/ThemeSelector.tsx`:
- Props: `{ theme: string, onThemeChange: (t: string) => void }`.
- Render: `<select>` (o gruppo di radio/button con `data-theme`) con le opzioni:
  `"90s-party"`, `"dark"`, `"cyberpunk"`.
  Etichette user-facing: "90's Party", "Dark", "Cyberpunk".
- Il selettore vive nella schermata Settings (sezione nuova "Aspetto"), iniettato
  da App.tsx via prop.

### 4. Wiring in App.tsx

- Sostituire il `data-theme="dark"` hard-coded in `index.html` con
  `data-theme="90s-party"` (fallback iniziale prima che l'hook legga la porta).
- Comporre `useTheme(makeThemePort(indexedDbConfig))` in App.
- Passare `theme` + `setTheme` a Settings tramite prop aggiuntive (non modifica
  l'interface di `SettingsProps` per i test legacy: le prop sono opzionali).
- Aggiungere `<ThemeSelector theme={theme} onThemeChange={setTheme} />` nella sezione
  "Aspetto" di Settings (dopo la sezione "Resa video" esistente).

### 5. index.html

Aggiornare il default `data-theme` da `"dark"` a `"90s-party"` in `<html>`.
