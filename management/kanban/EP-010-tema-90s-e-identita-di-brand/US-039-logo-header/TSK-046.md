# TSK-046 — Logo Soli-boy nell'header della schermata Library (US-039)

## Context

US-039 richiede che l'header della schermata Library (e per estensione Player e
Settings, se previsto dai mockup) mostri il logo Soli-boy. Gli SVG sono stati
copiati in `src/assets/` da TSK-042. La variante monocromatica (`soliboy-logo-mono.svg`)
eredita il colore dal contenitore via `currentColor`, garantendo coerenza col
tema SoliDS applicato. [^src: management/kanban/EP-010-tema-90s-e-identita-di-brand/US-039-logo-header/US-039.md §Business Rules]

## Technical Specs

### Scelta variante

**Decisione finale (impl):** `soliboy-logo-horizontal.svg` importato come URL
di default Vite (`import logoUrl from "...svg"`) e renderizzato come
`<img src={logoUrl} alt="Soli-boy">`. Motivazione: un `<img>` isola il
documento SVG dal CSS host e NON eredita `currentColor`; usando la mono via
`<img>` l'inchiostro sarebbe il nero fallback dell'SVG, illeggibile sui temi
scuri (es. `dark`, `90s-party`). La variante horizontal mantiene i colori del
brand ed è riconoscibile su qualsiasi tema senza dipendenze runtime aggiuntive.

**Gap svg-react-import-strategy — risolto con opzione zero-dep:** non aggiungiamo
`vite-plugin-svgr` (che abiliterebbe `?react` per ottenere SVG inline reattivi al
tema). Una versione theme-adaptive via inline SVG/svgr resta possibile come
miglioramento futuro se servirà un logo che si adatta al tema (cambio inchiostro
via `currentColor`); il follow-up dovrà valutare l'aggiunta del plugin o un
componente React custom che embedda l'SVG inline.

**Mockup non disponibili:** confermata in implementazione l'assunzione del TSK —
header in cima alla Library, sopra search/chip filtri. Reso in tutti gli stati
(error/loading/empty/populated) per coerenza branding.

### Modifica Library.tsx (impl finale)

`<header className="sd-flex sd-items-center sd-gap-md">` in cima alla Library con:
- `<img src={logoUrl} alt="Soli-boy" className="sb-app-logo" style={LOGO_STYLE} />`
  dove `logoUrl` deriva da `import logoUrl from "../../assets/soliboy-logo-horizontal.svg"`.
- Nessun colore hex hard-coded nel componente — i colori del brand sono dentro
  l'SVG, fuori scope CSS.
- Dimensione minima ≥ 16px applicata via `LOGO_STYLE` inline (`height: "2rem"`,
  `width: "auto"`, `display: "block"`).
- Classe `sb-app-logo` (no CSS associato) usata per il futuro tagging/override;
  NON usiamo `.sb-logo` esistente in `solids-theme.css` perché è scoped al box
  brand mark 34×34 (background + border-radius), incompatibile con la ratio
  680×240 dell'asset horizontal. `solids-theme.css` è fuori scope per questo TSK.

Header reso in tutti i branch di Library (error/loading/empty/populated) per
mantenere il brand visibile a prescindere dallo stato.

### Non duplicare favicon/manifest

Il logo SVG in header è una variante distinta dagli asset di `public/` usati da
TSK-043 e TSK-045; non sostituisce né duplica quelli. Gli AC di US-039 lo
confermano esplicitamente. [^src: management/kanban/EP-010-tema-90s-e-identita-di-brand/US-039-logo-header/US-039.md §Acceptance Criteria]
